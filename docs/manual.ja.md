# LiveCaption マニュアル

The English version is [manual.md](manual.md).

LiveCaption は、会議にリアルタイムの字幕を出すシステムです。現時点では、日本語と英語の
間で翻訳できます。

字幕の向きは選べます。

- **日本語の会議に英語字幕**（日本語を話さない参加者のため）
- **英語の会議に日本語字幕**（英語で聞き取るのが負担な参加者のため）

LiveCaption は Zoom に字幕を出せますが、Zoom 専用ではありません。音声は会議ソフトの
出す音をそのまま拾うので、音が出る会議ソフトなら何でも使えます。

**LiveCaption は会議に無言の参加者として入ります。** 自分では発言せず、聞こえた音だけを
字幕にします。無言の参加者にしている理由は「12. 仕組み」に書いてあります。

**動かし方は3通りあります。**

| 方法 | 要るもの | どんなとき |
|---|---|---|
| **Windows + Docker**（推奨） | Windows PC 1台と Docker Desktop | **ノートPC 1台で足ります。** 会議のたびに起こす |
| **Linux + Docker** | Linux 機 1台と Docker | 常時起動の機体に置いて、予定した会議に無人で入らせる |
| **Windows ネイティブ** | Windows PC 1台と VB-CABLE | Docker を入れない。**この方法は凍結してあります** |

Docker を使う2つの方法では、**会議ソフトも音声装置もコンテナの中にあります。**
機体に入れるのは Docker だけです。**自分は普段どおり同じ会議に参加できます。** 手順は
「2. インストール（Windows + Docker）」にあり、Linux の場合の違いは
「3. インストール（Linux + Docker）」にあります。

Windows ネイティブは「4. インストール（Windows ネイティブ）」にあります。
**凍結してあり、新しい機能は入りません。** 動いているものをそのまま残してあります。

**使い方は、どの方法でも同じです。** 操作画面も、予定も、用語対訳表も、会議の記録も
共通です。5章から先は、方法による違いがある所だけ明記してあります。

**予定を入れておけば、無人で動かせます。** 時刻が来たら Zoom に参加し、配信を始め、
会議が終わったら離脱して止まります。「6. 予定した会議の自動処理」を見てください。

## 1. 必要なもの

**どの方法でも要るもの:**

| 品目 | 補足 |
|---|---|
| OpenAI の APIキー | 文字起こしと翻訳の両方が OpenAI API を呼びます |
| Zoom など会議ソフトのアカウント | 無料のもので構いません |
| ホストまたは共同ホストの権限 | Zoom字幕API を使う場合だけ。他の見せ方には要りません |

**Docker で動かす場合:**

| 品目 | 補足 |
|---|---|
| 機体 1台 | Windows なら Docker Desktop（WSL2）。Linux なら Docker Engine。**音声装置も画面も要りません** |
| Docker と Docker Compose | Compose v2 以降 |
| Git | リポジトリを取ってくるのに使います |
| Tailscale のアカウント | 操作画面を開くのと、閲覧URLを外の参加者に配るのに使います。**操作画面は tailnet の中にしか出ないので、Docker では必須です。** 無料の範囲で足ります |

**Intel か AMD の機体が要ります。** イメージは amd64 だけなので、Apple Silicon の Mac
では動きません。Zoom が Linux の arm64 版を出していないためです。

**Windows ネイティブで動かす場合:**

| 品目 | 補足 |
|---|---|
| Windows PC 1台 | 字幕専用 |
| VB-CABLE | 無料の仮想オーディオケーブル。[vb-audio.com/Cable/](https://vb-audio.com/Cable/) |
| pixi | Python 環境を作ります。[pixi.sh](https://pixi.sh) |
| Git | リポジトリを取ってくるのに使います |

文字起こしの API料金は **$0.017/分** です。1時間の会議で約1ドル、日本円で150円ほどです。
翻訳のAPI料金は無視できるほど小さいです。

会議が無音の時間も課金されるので、休憩の間は「停止」を押すとよいでしょう。
**ただし「停止」は配信とZoom字幕も一緒に止めます**（5章の手順4を見てください）。
短い休憩なら、そのままにしておくほうが楽です。

## 2. インストール（Windows + Docker）

**この章が、インストールの基本です。** Linux で動かす場合も、まずこの章を読んでから、
「3. インストール（Linux + Docker）」で違う所だけを読み替えてください。

一度だけ据え付けます。**2章と3章では、Docker を動かす機体を「ホスト」と呼びます。**
Docker の言い方に合わせています。**5章から先の「ホスト」は、Zoom の会議のホストです。**
操作画面のボタンが「ホスト用URL」なので、そちらに合わせています。

ホストに入れるのは Docker だけです。**会議ソフトも、音声装置も、画面も、Tailscale も、
コンテナの中にあります。** ホストの音を使わないので、ホストで音楽を鳴らしても、
音量をいじっても、字幕には影響しません。

**この作りの利点は、ノートPC 1台で足りることです。** 自分は普段どおり Zoom に入って
発言し、コンテナの中の Zoom が無言の参加者として同じ会議に入ります。画面も音声装置も
分かれているので、ぶつかりません。**VB-CABLE も要りません。**

| | ホスト（自分） | コンテナ（字幕） |
|---|---|---|
| 会議ソフト | 通常の参加者。マイクもカメラも使う | 無言の参加者 |
| 画面 | 普段の画面 | コンテナの中（1600x1200 固定） |
| 音声 | ホストのスピーカーとマイク | コンテナの中の仮想の音声装置 |

Docker を使わない方法は「4. インストール（Windows ネイティブ）」にあります。
**そちらは凍結してあります。**

### 2.0 Docker Desktop のインストール

[docker.com](https://www.docker.com/products/docker-desktop/) から Docker Desktop を
入れます。**WSL2 が要ります。** インストーラが WSL2 を有効にします。

入れたあと、Docker Desktop を起動して、エンジンが上がるのを待ちます。上がったかどうかは、
次のコマンドで確かめます。

```powershell
docker version
```

**メモリ 16 GB の機体では窮屈かもしれません。** コンテナ自身は 220 MB ほどですが、
WSL2 がそれとは別にメモリを確保します。足りなければ `%USERPROFILE%\.wslconfig` で
WSL2 のメモリ上限を決めてください。

### 2.1 リポジトリの取得

```sh
git clone https://github.com/asoy01/LiveCaption.git
cd LiveCaption
```

以降のコマンドは、すべてクローンしたフォルダの中で実行します。

### 2.2 APIキーの設定

見本をコピーして、OpenAI のキーを書きます。

```sh
cp .env.example .env
```

```
OPENAI_API_KEY=sk-...
```

キーは [platform.openai.com](https://platform.openai.com) で作ります。

`.env` は Git に入りません（`.gitignore` に書いてあります）。**Docker のビルドコンテキストからも
外してあります**（`.dockerignore`）。キーがイメージの層に焼き付く事故は起きません。

`.env.example` には、他に設定できる項目も書いてあります。**いまは触らなくて構いません。**

### 2.3 Tailscale の準備

**閲覧URLを会議の参加者に配るのに Tailscale を使います。** コンテナ自身が tailnet の
1台のノードになり、配信を始めると Funnel で閲覧画面を外に出します。

操作画面も tailnet の中だけに出ます。**操作画面には認証がありません。** 守っているのは
「どこから届くか」だけなので、tailnet の外には出しません。

繋ぎ方は2通りあります。**まず (a) を試してください。** auth key を `.env` に置かずに
済みます。

#### (a) 手でのログイン

`.env` には何も足しません。`TS_AUTHKEY` の行はコメントのままにしておきます。

そのまま起動します（起動そのものは「2.5 起動」で説明します）。

```sh
docker compose up -d
docker compose logs -f
```

ログに、開くURLが出ます。

```
Tailscale:  TS_AUTHKEY が無い。下のURLを開いて手で繋ぐこと。

To authenticate, visit:

	https://login.tailscale.com/a/110e718b012a76

Tailscale:  アドレスがまだ無い。本体は背景で取り直す。
```

このURLをブラウザで開き、自分の Tailscale アカウントで承認します。

**承認を待たずに、LiveCaption は起動します。** 上のログの最後の行が、その状態を示しています。
承認が済むと、アドレスは裏で取り直されて、操作画面のURLがログに出ます。
**その場で承認できなくても、起動をやり直す必要はありません。**

**承認は一度だけで済みます。** 状態は `tailscale` ボリュームに残ります。
もう一度聞かれるのは、`docker compose down -v` でボリュームごと消したときだけです。

承認したノードには名前が付きます。既定は `livecaption` です。**2台以上で使うなら、
起動する前に `.env` で名前を変えてください。**

```
TS_HOSTNAME=livecaption-note
```

同じ名前を2台が名乗っても、共有はされません。あとから来たほうが `livecaption-1` に
付け替えられ、**前もって配った閲覧URLが使えなくなります。**

**(a) の方法では、ノードにタグが付きません。** そのため、管理画面での作業が2つ要ります。

- **Disable key expiry を有効にしてください。** 有効にしないと、既定の180日で
  ノードが tailnet から外れ、**閲覧URLが突然使えなくなります**
- **Funnel が使えるか確かめてください。** 既定の ACL では `autogroup:member` に
  `funnel` が付いていますが、ACL を書き換えている tailnet では外れていることが
  あります

**Tailnet Lock を使っている tailnet では、(a) でも署名が要ります。** コンテナは
署名鍵を持たないので、登録はされますが他のノードと通信できません。署名の仕方は
この節の最後にあります。

#### (b) auth key の使用

無人で立ち上げ直せるようにするなら、auth key を使います。
Tailscale の管理画面（Settings → Keys → Generate auth key）で作ります。

| 項目 | 値 | 理由 |
|---|---|---|
| Reusable | **on** | ボリュームを作り直すたびに要ります |
| Ephemeral | **off** | ephemeral のノードは名前が毎回変わり、**前もって配った閲覧URLが使えなくなります** |
| Tags | `tag:livecaption` | タグ付きのデバイスには鍵の期限が適用されません |

**タグは ACL に先に書いておきます。** Funnel を使うので、ノード属性も要ります。

```json
"tagOwners": { "tag:livecaption": ["autogroup:admin"] },
"nodeAttrs": [ { "target": ["tag:livecaption"], "attr": ["funnel"] } ]
```

**`nodeAttrs` の行を忘れないでください。** タグを付けたデバイスは `autogroup:member` から
外れるので、`nodeAttrs` が無いと Funnel を失います。

**タグを付けない場合は、管理画面で Disable key expiry を有効にしてください。**
忘れると、既定の180日でノードが tailnet から外れ、**閲覧URLが突然使えなくなります。**

できた鍵を `.env` に書きます。

```
TS_AUTHKEY=tskey-auth-xxxxxxxx
```

#### Tailnet Lock を使っている場合

**(a) と (b) のどちらでも署名が要ります。** コンテナは新しいノードで、署名鍵を
持ちません。署名の無いノードは、登録はされますが**他のノードと通信できません。**

Tailnet Lock を使っているかどうかは、署名鍵を持っている機体で確かめられます。

```sh
tailscale lock status
```

`Tailnet Lock is NOT enabled.` と出たなら、この節は読み飛ばしてください。

**(b) auth key を使う場合は、鍵に署名します。** 署名鍵を持っている機体で次を実行し、
出てきた署名済みの鍵を `.env` の `TS_AUTHKEY` に書きます。

```sh
sudo tailscale lock sign tskey-auth-xxxxxxxx
```

**署名済みの鍵で登録したノードには、登録の時点で署名が付きます。** その鍵は
reusable なので、**1本で何台でも署名済みのノードを立てられます。**

**(a) 手でログインする場合は、ノード鍵に署名します。** 承認したあと、コンテナの
中で次を実行するとノード鍵が出ます。

```sh
docker compose exec engine tailscale lock status
```

その鍵に、署名鍵を持っている機体で署名します。

```sh
sudo tailscale lock sign nodekey:xxxxxxxx
```

**署名は一度きりです。** 状態は `tailscale` ボリュームに残ります。

**署名済みの auth key は、扱いに気をつけてください。** その鍵自体が「信頼された
署名鍵」として tailnet に登録されるので、**鍵を持っている人は、署名済みで
信頼されたノードを好きなだけ足せます。** Tailnet Lock の保護をそのまま迂回できて
しまいます。**この点でも (a) のほうが安全です。**

#### 操作画面に届く端末の制限

**ACL で、操作画面に届く端末を自分のものだけに絞ってください。** tailnet に他の人を
招いている場合、絞らないと、その人たちも操作画面を開けます。開ければ、終了も、
配信の開始も、**会議の文字起こしの閲覧**もできます。

### 2.4 機体ごとの設定

**1つめは `TS_HOSTNAME` です。** 2.3 で説明したとおり、2台以上で使うときに変えます。

**2つめは常駐です。会議のときだけ起こす使い方なら、切ってください。**
切らないと、Docker Desktop を立ち上げるたびに LiveCaption が上がり、予定を
入れてあれば Zoom にまで入ります。

```
LIVECAPTION_RESTART=no
```

こうすると、会議のたびに `docker compose up -d` で起こし、終わったら
`docker compose down` で落とす使い方になります。**操作画面のボタンの文字も
変わります**（6.6）。**常時起動の機体に置くなら、この行は書かないでください。**

### 2.5 起動

```sh
docker compose up -d --build
```

初回はイメージを作るので10分ほどかかります。**2回目からは数秒です。**

立ち上がったかどうかはログで見ます。

```sh
docker compose logs -f
```

```
音声:       meeting / mic を作った。本体は meeting.monitor から録る
Tailscale:  100.x.x.x  (livecaption.<tailnet>.ts.net)
用語集:     /app/local/glossary（3 個）
画面:       :99 (1600x1200x24)
Zoom:       設定を書いた（speaker_volume=255）
操作        https でも開ける: https://livecaption.<tailnet>.ts.net:8443
操作画面:   http://localhost:8081  （自分だけ。共有しないこと）
            http://livecaption.<tailnet>.ts.net:8081  （tailnet の中から。ACLで絞ること）
```

**この `https://...:8443` が、普段使う操作画面です。** tailnet に入っている端末の
ブラウザから開きます。証明書は Tailscale が取得し、期限が来ると自動で更新します。

**完全な名前で開いてください。** 証明書は `<機体>.<tailnet>.ts.net` に対して出るので、
短い名前やIPアドレスでは合いません。

2.3 で (a) を選んだ場合は、ここでログに認証のURLが出ます。ブラウザで開いて承認すると、
アドレスが付きます。**LiveCaption は裏でアドレスを取り直すので、起動をやり直す必要はありません。**

**ホストを再起動しても、コンテナは自分で戻ってきます**（`restart: unless-stopped`）。
常時起動の機体に置いて、予定した会議に備えるための設定です。

### 2.6 Zoom へのサインイン

**コンテナの中の Zoom は、最初サインインしていません。** 会議に自動で参加させるには、
一度だけ人の手でサインインします。**VNC を使います。**

操作画面の**設定**タブ →「VNC」→「起動」を押します。出てくるURLをブラウザで開くと、
コンテナの中の画面が見えます。

```
https://livecaption.<tailnet>.ts.net:6443/vnc.html
```

Zoom の窓でサインインし、終わったら「停止」を押します。**サインインの状態はボリュームに
残るので、次からは要りません。**

**VNC にはパスワードがありません。** 守っているのは tailnet の境目だけです。
**使うときだけ起動して、終わったら止めてください。** 会議の最中でも起動・停止できます。

**コンテナの中で端末も開けます。** 何も無い所で右クリック → `Terminal emulator`。

### 2.7 用語対訳表の用意

**このリポジトリには表が入っていません。** `etc/glossary/` は空です。表は分野ごとに
違うので、自分のものを用意してください。書式と作り方は「7. 用語対訳表」にあります。

`docs/glossary-example.tsv` に見本があります。

Docker で動かす場合、表は**操作画面からアップロードします**（設定タブ →「用語集」）。
**ボリュームの中に保存されるので、コンテナを作り直しても消えません。**
ダウンロードと削除も同じ場所からできます。

### 2.8 動作の確認

会議に入らずに、録音した音で一通り試せます。

```sh
docker compose run --rm -v "$PWD/録音:/samples:ro" engine \
  --from-file /samples/test.wav --dry-run
```

`--dry-run` を付けると、Zoom へは何も送りません。文字起こしと翻訳だけを見られます。
音は 24000 Hz のモノラル WAV にしておきます。

## 3. インストール（Linux + Docker）

**常時起動の Linux 機に置く場合です。** 予定した会議に無人で入らせるなら、この形が
向いています。機体が寝ていると、予定の時刻に動けません。**サスペンドしない設定に
しておいてください。**

**手順は2章と同じです。違うのは3か所だけです。** 2章を読みながら、2.0 と 2.4 を
下のもので読み替え、3.2 を足してください。

### 3.1 Docker のインストール（2.0 の読み替え）

Docker Desktop ではなく、Docker Engine と Compose を入れます。入れ方は
[docs.docker.com](https://docs.docker.com/engine/install/) にあります。
**Compose は v2 以降が要ります。**

自分を `docker` グループに入れておくと、`sudo` が要らなくなります。

```sh
sudo usermod -aG docker $USER
```

**実行したあとは、ログインし直してください。** ログインし直さないと、グループの変更が
効きません。

### 3.2 ConnMan を使っている機体での設定（2章には無い節）

**ネットワーク管理が ConnMan の場合は、先に ConnMan の設定を直してください。**
ConnMan は Debian の一部の構成や、組み込み向けの機体で使われています。使っているか
どうかは、次のコマンドで分かります。使っていなければ、この節は飛ばして構いません。

```sh
systemctl is-active connman
```

ConnMan は見つけた機器を全部管理しようとしますが、**既定の除外一覧に `docker`・
`veth`・`br-`・`tailscale` が入っていません。** そのため Docker の作る仮想の線を掴み、
DHCP に失敗し、リンクローカルのアドレスを振り、**ホストの既定経路までその線へ向けます。**
ホストの外向き通信が、コンテナの中へ吸い込まれて消えます。

**症状が分かりにくいので注意してください。** DHCP の待ち時間があるので、**コンテナの
起動から数十秒遅れて**ホストの通信が壊れます。Zoom から見ると「入室はできるが、30〜40秒後に音声を
失って切断」という形になります。

`/etc/connman/main.conf` に次を書きます。

```
NetworkInterfaceBlacklist = vmnet,vboxnet,virbr,ifb,ve-,vb-,docker,veth,br-,tailscale
```

書いたら、ConnMan と tailscaled を再起動します。

```sh
sudo systemctl restart connman
sudo systemctl restart tailscaled
```

**`tailscale` も忘れずに除外一覧へ入れてください。** `docker` だけを除外すると、今度は
ConnMan が `tailscale0` を掴んで落とします。**このとき `tailscale status` は「Online: True」と表示します。**
制御サーバとの接続は有線側を通っているので、状態表示では気づけません。壊れているのは
データの通り道だけです。確かめるには次のコマンドを使います。

```sh
ip addr show tailscale0
```

### 3.3 機体ごとの設定（2.4 の読み替え）

**常駐させます。** `LIVECAPTION_RESTART` は書かないでください。既定の
`unless-stopped` のままにすると、ホストを再起動してもコンテナが自分で戻ってきます。
予定した会議に備えるには、この常駐が要ります。

`TS_HOSTNAME` は2章と同じで、2台以上で使うときだけ変えます。

**残りの手順（2.1〜2.3、2.5〜2.8）は、そのまま同じです。**

## 4. インストール（Windows ネイティブ）

**この方法は凍結してあります。** 動いているものをそのまま残していますが、新しい機能は
入りません。これから据え付けるなら「2. インストール（Windows + Docker）」のほうを
使ってください。

**この方法では、字幕のための Windows PC を1台用意します。** 以下ではこれを
「字幕PC」と呼びます。**その PC は会議に無言の参加者として入るので、自分が
発言に使う PC とは別に要ります。** Docker の2つと違うのはここです。

インストールは字幕PCで一度だけ済ませます。

### 4.1 VB-CABLE のインストール

[vb-audio.com/Cable/](https://vb-audio.com/Cable/) からダウンロードします。
**インストーラは管理者権限で実行し、終わったら PC を再起動してください。**

### 4.2 CABLE の周波数設定（48000 Hz）

再起動後、Windows のサウンド設定で次の2つを確認します。

| デバイス | 形式 |
|---|---|
| `CABLE Input`（再生） | **48000 Hz**、16ビット |
| `CABLE Output`（録音） | **48000 Hz**、16ビット |

**両方を 48000 Hz に揃えてください。** 食い違うと Windows が再サンプリングし、音が
乱れます。LiveCaption は 48000 Hz で開いて、自分で 24000 Hz に落とします。

### 4.3 pixi のインストール

pixi は Python の環境を作るソフトです。**Python を別に入れる必要はありません。** pixi が
必要なバージョンの Python ごと用意します。

PowerShell を開いて、次のどちらかを実行します。

```powershell
winget install prefix-dev.pixi
```

```powershell
powershell -ExecutionPolicy ByPass -c "irm -useb https://pixi.sh/install.ps1 | iex"
```

**pixi を入れたあとは、PowerShell を開き直してください。** 開き直さないと、PATH の変更が
反映されません。pixi が入ったかどうかは、次のコマンドで確かめます。

```powershell
pixi --version
```

Git も同じように入れられます。既に入っていれば飛ばしてください。

```powershell
winget install Git.Git
```

### 4.4 リポジトリの取得

置き場所はどこでも構いません。日本語やスペースを含まないパスにしておくと安全です。

```powershell
cd C:\src
git clone https://github.com/asoy01/LiveCaption.git
cd LiveCaption
```

Git を使わない場合は、GitHub のページから ZIP をダウンロードして展開しても構いません。
ただし、ZIP を展開した場合は `git pull` で更新できなくなります。

### 4.5 Python 環境の構築

クローンしたフォルダの中で実行します。

```powershell
pixi install
```

必要なパッケージが `.pixi` フォルダの中に入ります。**pixi はシステムの Python を変更しません。**
初回は数分かかります。

### 4.6 APIキーの設定

**置き場所はリポジトリの直下です。** `pixi.toml` や `StartLiveCaption.bat` と同じ
フォルダに、`.env` という名前のファイルを作ります。

```
LiveCaption\
  ├ .env.example          見本。リポジトリに入っています
  ├ .env                  これを作ります
  ├ pixi.toml
  ├ StartLiveCaption.bat
  ├ src\
  └ ...
```

4.4 でクローンしたフォルダの中で、見本をコピーするのが早いです。

```powershell
copy .env.example .env
notepad .env
```

開いたら、キーを書き込んで保存します。

```
OPENAI_API_KEY=sk-...
```

キーは [platform.openai.com](https://platform.openai.com) で作ります。

**ファイル名は `.env` です。`.env.txt` ではありません。** メモ帳の「名前を付けて保存」で
新規に作ると `.txt` が付くことがあります。上の `copy` を使えば `.txt` は付きません。

`.env` は Git に入りません（`.gitignore` に書いてあります）。キーが誤って公開される心配は
要りません。

**`.env` の値が、同じ名前の環境変数より優先されます。** 両方に書いた場合、使われるのは
`.env` のほうです。

### 4.7 音声経路の確認

この確認に会議も APIキーも要りません。`CABLE Input` にサイン波を流しながら、
`CABLE Output` から読み返します。

```powershell
pixi run python scripts/cable_loopback.py
```

送った振幅が返ってくれば、VB-CABLE は正常です。

```
--- 本体が既定で選ぶもの: 2 'CABLE Output (VB-Audio Virtual ' [MME] ---
  区間 39、音あり 39（100%）  最大 peak 0.299  取りこぼし 0
  => 通っている
```

### 4.8 スタートメニューへの登録（任意）

**`InstallToStartMenu.bat`** をダブルクリックします。現在のユーザーのスタートメニューに
`LiveCaption` の項目が入るので、会議の前にリポジトリのフォルダを探さずに済みます。

**この項目はウィンドウを開きません。** タスクトレイに常駐し、アイコンを右クリックして
操作画面・ログ・終了を選びます（6.6 を見てください）。起動の様子を見たいときは、
`StartLiveCaption.bat` を手で実行してください。そちらはコンソールが残ります。

```
Windowsキー  ->  「livecaption」と打つ  ->  Enter
```

目に入る場所に置きたければ、スタートメニューの LiveCaption を右クリックして
**スタートにピン留めする** か **タスクバーにピン留めする** を選びます。

管理者権限は要りません。作られるのはショートカット1つで、置き場所は
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\LiveCaption.lnk` です。

**リポジトリのフォルダを移動・改名したら、`InstallToStartMenu.bat` をもう一度実行してください。**
ショートカットは絶対パスを持っているので、フォルダを動かすと LiveCaption を開けなくなります。

アイコンは `etc/LiveCaption.ico` を使います。アイコンを変えるときは `scripts/make_icon.py` を
直して実行し、登録し直してください。登録を消すときは、PowerShell から `-Remove` を付けて実行します。

```powershell
InstallToStartMenu.bat -Remove
```

### 4.9 遠隔操作の注意

字幕PCを別の部屋に置いて遠隔操作しても構いません。**ただし RDP（リモートデスクトップ）は
使えません。**

RDP は別のセッションを作ってコンソールセッションをロックし、音声を「リモートオーディオ」
へ振り替えます。**会議ソフトが選んでいた `CABLE Input` への経路が切れて、字幕が止まります。**

VNC 系のように、コンソールセッションをそのまま操作するソフトを使ってください。VNC 系なら
オーディオデバイスの構成は変わりません。

### 4.10 操作画面の遠隔利用（任意）

画面を丸ごと転送する遠隔操作は、遅延があって扱いにくいことがあります。操作画面は Web
ページなので、**別の端末のブラウザから直接開くほうが速くて確実です。**

Tailscale を使っている場合、次のように起動すると、操作画面が tailnet のアドレスでも
開けるようになります。

```
pixi run caption --web --control-bind
```

値を省くと、LiveCaption が字幕PCの Tailscale アドレスを調べます。起動時に次のように出ます。

```
操作画面:   http://localhost:8081  （自分だけ。共有しないこと）
            http://100.x.x.x:8081  （tailnet の中から。ACLで絞ること）
```

**127.0.0.1 は必ず残ります。** Tailscale が落ちていても、機体の前からは操作できます。
再起動の直後で Tailscale がまだ上がっていない場合は、アドレスが取れるまで LiveCaption が裏で試し直します。

**操作画面には認証がありません。** 守っているのは「どこから届くか」だけです。したがって:

- **tailnet の外には絶対に出さないでください。** Tailscale の範囲
  （`100.64.0.0/10`、`fd7a:115c:a1e0::/48`）以外のアドレスは受け付けない作りにしてあります
- **Tailscale の ACL で、届く端末を自分のものだけに絞ってください。** tailnet に他の人を
  招いている場合、絞らないと、その人たちも操作画面を開けます。開ければ、
  終了も、配信の開始も、**会議の文字起こしの閲覧**もできます

平文の HTTP になるので、**「URLをコピー」のボタンは効きません**（ブラウザの制限です）。
URLは選択された状態になるので、Ctrl+C でコピーしてください。機体の前で `localhost` から
開いたときは、このボタンは効きます。

## 5. 使用方法

### 手順1. アプリの起動

**Docker の場合、起動は要りません。** コンテナは常に動いています。ブラウザで操作画面を
開くだけです。

```
https://livecaption.<tailnet>.ts.net:8443    操作画面   <- この画面は共有しないこと
```

閲覧URLは会議ごとに違います。操作画面の「この会議」タブに出ます。

**Windows ネイティブの場合**は、**`StartLiveCaption.bat`** をダブルクリックします。
4.8 で登録してあれば、スタートメニューの **LiveCaption** からでも構いません。
操作画面がブラウザで開きます。

```
http://localhost:8081              操作画面   <- この画面は共有しないこと
http://localhost:8080/v/<ランダム>  閲覧画面   <- 共有するのはこちら
```

**操作画面を絶対に画面共有しないでください。** Zoom の字幕トークンが映っています。

**LiveCaption は、字幕の生成を止めた状態で始まります。** **開始**を押すまで、音は
取り込まれず、API も呼ばれません。会議に入る前に立ち上げておけます。準備中の雑談は
文字起こしに流れません。

#### 操作画面の見方

左が字幕、右が操作です。境目をドラッグすると幅が変わり、ダブルクリックで元に戻ります。

右は3枚のタブに分かれています。

| タブ | 中身 | いつ見るか |
|---|---|---|
| **この会議** | いまの状態・配信する会議・見せ方・会議の記録 | 会議のたび |
| **会議の管理** | 予定の追加・入力・削除 | 会議の前に |
| **設定** | 音声の入力・用語集・遅延の調整・アプリの終了 | 据え付けるとき |

**当日触るものは、すべて「この会議」の側にあります。** 設定の側は、一度合わせたらほとんど
開きません。

**「会議の管理」は右の欄の中に開きます。** 字幕はそのまま左に残ります。

**欄の幅はタブを変えても動きません。** 管理の画面が狭いときは、境目を引いて広げて
ください。中身はその幅に合わせて伸びます。

**「この会議」に赤い丸が付いたら、そのタブの中で何かが失敗しています。** 他のタブを開いた
ままでも気づけるように出しています。

いちばん上の「見せ方」の3つは畳んであります。**畳んだままでも、見出しの右に
`配信中` や `送信中` と出るので、いくつ動いているかは分かります。**

操作画面は日本語と英語を切り替えられます。ヘッダの **日本語 / English** の欄で選ぶと、
その場で読み込み直します。**次の起動もその言語で始まります。**

**切り替わるのは操作画面だけです。** 字幕そのもの、文字起こし、会議の記録は訳しません。
閲覧画面は元から英語です。

### 手順2. 会議への参加

**Docker の場合、LiveCaption が自分で入ります。** **会議の管理**タブに Zoom の招待URLを
入れておくと、「この会議をいま始める」を押したとき、または予定の時刻が来たときに、自分で参加
します。音声の出力先もマイクのミュートも表示名も、コンテナの中で設定済みです。
詳しくは「6. 予定した会議の自動処理」を見てください。

**会議に入れたかどうかは、手順4の音量メーターで分かります。** 参加に失敗したときは、操作画面の VNC を起動すると、
Zoom の窓が何で止まっているか（待機室、パスコード、サインイン切れ）が見えます。

**Windows ネイティブの場合**は、字幕PCの会議ソフトで、次の3つを確かめます。

- **音声の出力先: `CABLE Input`。** 出力先が違うと、音が LiveCaption に届きません
- **マイク: ミュート。** この PC は発言しません
- **表示名: `Live Captions` など。** 参加者一覧に出るので、字幕PC が何をしているか
  分かるようにします

そのうえで会議に入ります。

### 手順3. 入力デバイスの確認

操作画面の**設定**タブを開き、「音声の入力」を見ます。

**Docker の場合は `pulse` です。** コンテナの中の仮想の音声装置で、Zoom がここへ音を
出し、LiveCaption がその音を拾います。**据え付けたあとは触りません。**

**Windows ネイティブの場合は `CABLE Output` です。** 違っていたら一覧から選んで
ください。**選んだ時点で切り替わります。適用ボタンはありません。**
あとから挿したデバイスが一覧に無ければ「一覧を更新」を押します。

一覧には名前だけでなくホストAPIも出ます。Windows では `CABLE Output` が
MME・DirectSound・WASAPI の3つに現れるためです。

```
2: CABLE Output (VB-Audio Virtual （MME、16 ch）
```

3つのどれでも動きます。既定は MME です。MME のままで構いません。

### 手順4. 字幕の向きの確認と生成の開始

操作画面の**この会議**タブで、「字幕の向き」を見ます。**会議ごとに選びます。**

| 選ぶもの | どんな会議か | 出る字幕 |
|---|---|---|
| 日本語 → 英語 | 日本語で行う会議 | 英語 |
| 英語 → 日本語 | 英語で行う会議 | 日本語 |

**選んだ時点で切り替わります。適用ボタンはありません。** 会議の途中で変えても構いません。
文字起こしは繋ぎ直さないので、字幕の生成を止めずに切り替えられます。

**逆の言語が混ざったときは、訳さずにそのまま出します。** 日本語 → 英語 の会議で英語の
発言が来たら、その英語をそのまま字幕にします。**前半が英語で後半が日本語といった会議
でも、片方を選んでおけば足ります。**

**次の起動もこの向きで始まります。** 前回の選択を覚えています。

そのうえで、いちばん上の「いまの状態」の**開始**を押します。

**「停止」は3つとも止めます。** 字幕の生成だけでなく、参加者への配信（閲覧URL）と
Zoom字幕への送信も一緒に閉じます。**止めたつもりで字幕が流れ続けるのを防ぐ**ためです。
配信を止めると閲覧URLは使えなくなるので、休憩のたびに押すものではありません。
何を止めたかは、押した後にその場に出ます。

**その下の音量メーターを見てください。** 誰も喋っていなければメーターは振れません。誰かに喋って
もらいます。人が喋っているのにメーターが振れないなら、入力デバイスが違います。別のデバイスを
選んでください。**生成中でも差し替えられます。**

### 手順5. 字幕の表示方法

字幕の見せ方は3つあります。**3つとも同時に使えます。**

| 方法 | ホスト権限 | 読み手がすること | 外に出るか |
|---|---|---|---|
| Zoom字幕API | **要る** | 各自が手動字幕をオンにする | Zoom経由 |
| 画面共有 | 要らない | 閲覧画面を全画面にして共有する | **出ない** |
| URL配布 | 要らない | 各自の端末でURLを開く | Cloudflare か Tailscale 経由 |

#### A. Zoom字幕API（ホストまたは共同ホストの権限が必要）

トークンは会議中にしか作れません。作れるのはホストと共同ホストだけです。

1. ホストがツールバーの「字幕」の横の矢印を押し、**「手動字幕の設定」**を開いて、
   手動字幕を有効にします。**これを先にしないと「APIトークンをコピー」は出てきません**
2. 同じ場所から **「APIトークンをコピー」** を選びます
3. ホストがそのトークンを、会議のチャットなどで自分に送ります
4. 操作画面の「見せ方」で **Zoomの字幕に流す** を開き、「APIトークン」にトークンを
   貼って**登録**を押します。入力欄は伏せ字で、登録すると空になります
5. **開始**を押します。まず捨て字幕が3つ流れます。**受信側は、字幕が流れ始めるまで
   手動字幕をオンにできません。** 最初の数行は誰にも届かないので、意味の無い
   3行を先に送っておきます

**Zoom の自動字幕をオフにしてください。** オンのままだと、LiveCaption の字幕が
押し出されて読めなくなります。

**操作画面の右上の表示を見てください。**

| 表示 | 意味 |
|---|---|
| `Zoom: 未登録` | トークンがまだ入っていない |
| `Zoom: 停止中` | 登録済み。「開始」を押せば送る |
| `Zoom: 送信中` | 送っている |
| `Zoom: 送信中（失敗 3）` | **送信が失敗している。** トークンが切れたか、会議が変わった |
| `生成: 停止中` | **字幕を作っていない。** Zoom を送信中にしても1行も流れない |
| `生成: 中` | 字幕を作っている |

**失敗の数を見逃さないでください。** Zoom は間違ったトークンに 200 以外を返すだけで、
理由を教えません。トークンを取り直して登録し直します。

#### B. 画面共有

ホスト権限が要らず、字幕が外に出ません。**共有するのは、自分が会議に出ている PC の
画面です。** 字幕の機体の画面ではありません。

1. 操作画面の「見せ方」で **画面共有で見せる** を開き、**閲覧画面を開く**を押します
2. **F11** で閲覧画面を全画面にします
3. 会議ソフトでそのブラウザの画面を共有します

**Docker の場合、閲覧画面は tailnet の名前で開きます。** 操作画面を開いている端末が
tailnet に入っていれば、そのまま開きます。入っていない端末に見せるなら、C の
URL 配布を使ってください。

**画面共有の映像は圧縮されます。** 小さい字は潰れます。共有を始めた後、2台目の端末から
字幕が読めるかどうか確かめてください。読めなければ行数を減らします（`config.WEB_LINES`）。

#### C. URL の配布

URL の配布もホスト権限が要りません。字幕の機体から外向きにトンネルを張り、閲覧URLと
QRコードを作ります。

**Docker の場合、経路は Tailscale です。** コンテナに `cloudflared` は入っていないので、
下の C-1 は使えません。C-2 を読んでください。準備は 2.3 で済んでいます。

**経路は2つあります。** 「見せ方」→ **ブラウザで見てもらう** を開いて、「経路」で選びます。

| | Cloudflare | Tailscale |
|---|---|---|
| 準備 | 字幕PCに `cloudflared` を入れます | tailnet の設定が1回 |
| URL | **配信のたびに変わります** | **変わりません** |
| 前もって配れるか | 配れません | **配れます** |

その場で決まった会議には Cloudflare、前もって案内に載せたい会議には Tailscale を使います。

##### C-1. その場での配布（Cloudflare）

**先に `cloudflared` を字幕PCに入れてください。** 入っていないと、配信の開始が
失敗して、入れ方が画面に出ます。次のどちらかで入れます。

```powershell
winget install --id Cloudflare.cloudflared
```

または、[cloudflared-windows-amd64.exe](https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe)
を落として、リポジトリの `local/bin/cloudflared.exe` に置きます。PATH に入れても
構いません。別の場所に置く場合は `--cloudflared <パス>` で教えます。

1. 「経路」を **Cloudflare** にします
2. **配信を開始**を押します。表示が `配信: 起動中…` から `配信: 中` に変わります
3. 字幕を見たい人にQRコードを見せるか、URLを送ります。
   **URLの下の「URLをコピー」を押せば、そのままチャットに貼れます**
4. QRコードを画像で配りたいときは、**「QRコードを保存」**を押します。PNG
   （656×656 ピクセル）がブラウザのダウンロードフォルダに落ちるので、
   案内のメールやスライドに貼れます
5. 各自が自分のスマホやノートで開きます

##### C-2. 事前の配布（Tailscale）

ホスト名が変わらないので、**会議の前日でもURLが決まります。** Zoomのリンクと
一緒に案内に載せられます。

準備は1回だけです。**Docker の場合は 2.3 で済んでいます。**

Windows ネイティブの場合は、字幕PCで次を実行し、ブラウザに出る同意のページで承認します。
tailnet の管理者権限が要ります。

```
tailscale funnel 8080
```

有効になるのは、HTTPS証明書と、ポリシーの `funnel` 属性の2つです。

会議ごとの手順は次のとおりです。

1. 「経路」を **Tailscale** にします
2. 「会議」に会議の名前を入れて**追加**を押します。その会議のURLがその場で出ます
3. URLをコピーするか、QRコードを保存して、案内に載せます
4. **当日、その会議を選びます。** 左の丸印を押すと、配信する会議が切り替わります
5. **配信を開始**を押します

**配信するのは選んである1つだけです。** 他の会議のURLは、その日には開けません。
先週の会議の参加者が、今日の字幕を見ることはありません。

**URLが固定である点は、弱点でもあります。** 守っているのはURLの後半の文字列だけなので、
漏れたら会議を消して作り直してください。

**どちらの経路でも、配信を開始するまでは何も出ません。** ただし始めれば、字幕は
Cloudflare か Tailscale を通って外に出ます。
**外部に出せない内容を扱う会議では、URL の配布を使わないでください。**
代わりに画面共有を使います。

### 手順6. 参加者への案内

会議の冒頭で、字幕を読む人に次を伝えます。

- **各自が手動字幕をオンにすること。** オンにした人にしか字幕は見えません
- **字幕の表示領域をドラッグして広げること。** 既定は4行です。4行では翻訳を読む余裕が
  ありません

### 手順7. 終了

**会議ごとにアプリを終了する必要はありません。** 字幕の生成を止めれば、API も呼ばれず、課金も
止まります。次の会議までそのままにしておけます。

アプリ自体を終わらせたいときは、操作画面の**設定**タブを開きます。

**Docker の場合は「アプリの再起動」です。** 押すとコンテナが落ち、数秒で戻ってきます。
外から操作画面だけで使うので、押しても止まったままにはなりません（6.6）。

**Windows ネイティブの場合は「アプリの終了」です。** ブラウザのタブもターミナルの
ウィンドウも閉じます。タスクトレイから起動した場合は、アイコンを右クリックして
**終了**でも同じです。

## 6. 予定した会議の自動処理

ここまでは、会議のたびに人が操作画面の前に座る使い方です。**予定を入れておけば、
時刻が来たときに自動で動かせます。** 字幕の機体を常時起動しておく運用を想定しています。
**Docker で常時起動の機体に置いているなら、これが普通の使い方になります。**

自動で行うのは次の4つです。

1. 会議を選び、配信を開始する
2. Zoomに参加する
3. 字幕の生成を開始する
4. 会議が終わったら、離脱して停止する

**字幕APIトークンだけは自動で取れません。** 会議中にホストしか作れないためです。
受け取り方は「6.5 ホスト用URL」にあります。

### 6.0 予定を待たない開始

**同じ4つを、いま実行することもできます。** 予定を入れていない会議や、予定より
早く始まった会議のためのものです。

操作画面の**この会議**タブで会議を選び、**この会議をいま始める**を押します。
ボタンの下に、その会議で何が起きるかが出ます。

```
配信 → Zoomに入る → 字幕の生成 → チャットに投げる
```

Zoomに入るのはURLが入っている会議だけ、チャットに投げるのは印が付いている会議
だけです（どちらも「会議の管理」で設定します）。**チャットへの投稿は、押した時と
3分後の2回です**（予定の回では、定刻と3分後）。

**始まるまで数十秒かかります。** Zoomの起動と配信の立ち上げを含むためです。
進み具合は「いまの状態」に出ます。止めるときは**いま止める**を押します。

いちばん上の**開始**とは別のものです。開始のほうは、音の取り込みと文字起こしだけを
始めます。**配信もZoomも、開始では動きません。**

### 6.1 予定の入力

操作画面の**会議の管理**タブを選びます。会議の行に、そのまま入力欄が並んでいます。

操作画面のURLに `/meetings` を足して直に開いても、同じものが出ます
（Windows ネイティブなら `http://localhost:8081/meetings`、Docker なら
`https://livecaption.<tailnet>.ts.net:8443/meetings`）。

| 欄 | 意味 |
|---|---|
| 開始 | 会議の開始時刻 |
| 毎週 | 同じ曜日・同じ時刻で繰り返す |
| Zoom | 招待URL（`https://zoom.us/j/...`）か会議番号。空なら自分では参加しません |
| 何分前から | この分だけ前に、配信とZoom参加を始めます。既定は2分 |
| 無音で終了（分） | 文字起こしがこの分だけ出なければ、会議が終わったとみなします。既定は10分 |
| 安全上限（分） | 無音でなくても、この時間で必ず止めます。既定は180分 |
| この会議を自動で開始する | **この印が付いた会議だけが自動で動きます** |

**「自動で開始する」の既定は切りです。** 自動で開始すると、人が見ていなくても字幕が
外に出ます。
外に出せない内容を扱う会議には、印を付けないでください。

繰り返しは「毎週」だけです。より複雑な予定は入れられません。

### 6.2 動作の確認

操作画面の**この会議**タブのいちばん上、「いまの状態」に出ます。

```
いまの状態
[開始] [停止]  止まっている
待機中
2026-09-25 10:00  KAGRA朝礼         あと 23 分
2026-09-27 13:00  共同研究者会議     あと 2 日 3 時間
[いま止める] [次の予定を飛ばす]
```

動いている間は、無音で終了するまでの残り時間と、安全上限までの残り時間が出ます。

**失敗は、押して消すまで残ります。** 無人で動かす以上、画面から消えてしまった失敗は
誰も気づきません。内容を確かめたら「了解」で消してください。

**「次の予定を飛ばす」** は、その回だけ休むときに使います。予定そのものは残ります。

### 6.3 Zoomのチャットへの投稿

**字幕が出たら、会議のチャットに閲覧URLとQRコードを投げられます。** 会議の管理で
「字幕が出たら、ZoomのチャットにURLとQRを投げる」に印を付けてください。**既定は切りです。**

投げる文面は英語で固定です。

```
Live captions for this meeting (Japanese to English):
https://livecaption.<tailnet>.ts.net/v/xxxxxxxx
Open the link in any browser. No app or sign-in needed.
```

**URLを先に、QRコードを後に投げます。** ホストがファイル送信を切っている会議では
QRコードが弾かれますが、**URLは先に届いています。**

#### 投げる時刻

**2回投げます。予定の開始時刻と、その3分後です。** 内容は同じです。
LiveCaption が動き出すのは開始の数分前ですが、**そのときは投げません。**

理由は Zoom の作りです。**Zoom のチャットは、自分が入る前の発言が見えません。**
定刻より前に投げると、定刻に入ってきた人には何も残りません。2回投げるのは、
少し遅れて入ってきた人にも届かせるためです。

**それでも、3分より後に入ってきた人には届きません。** これは Zoom の制限で、
こちら側ではどうにもなりません。遅れて入る人が多い会議では、Zoomの招待に閲覧URLも
書いておくか、会議の途中で**Zoomのチャットに投げる**を手で押してください。

**Zoom への参加が遅れて1回目の投稿が定刻より後になったときは、2回目まで1分以上あけます。**
同じ文が数秒差で2つ並ぶと、壊れているように見えるためです。

投げる時刻は `.env` からは変えられません。変えるなら
`src/live_caption/config.py` の `SCHEDULE_CHAT_AT_MIN` を直します。

**Zoom が会議に入り終えるのも待ちます。** `zoommtg:` を投げてから会議の窓が出るまで、
Zoom は数十秒から数分かかります。窓が出るまで10秒ごとに見に行き、10分待って出て
こなければ、諦めたことをログに残します。

手で投げたいときは、操作画面の「見せ方」→ **ブラウザで見てもらう** の中にある
**Zoomのチャットに投げる**を押します。いま入っている会議に、その場で投げます。

#### 仕組みと、その弱さ

**Zoom に「会議中のチャットへ投稿する」APIはありません。** LiveCaption は Zoom の窓を
画面操作で動かしています。したがって次の弱さがあります。

- **Zoom の作りが変われば、黙って効かなくなります。** 窓の名前で見分けているためです
- **届いたかどうかは、こちらから確かめられません。** 送ったところまでしか分かりません
- **クリップボードを一時的に使います。** 文字は退避して戻しますが、**画像やファイルを
  入れていた場合は失われます**
- 投げるあいだ、Zoom のチャット窓が前面に出ます

**Docker の場合、Zoom の窓はコンテナの中にあります。** 誰にも見えないので、画面共有に
映る心配はありません。クリップボードもコンテナの中のもので、操作している端末のものは
触りません。

**Windows ネイティブの場合は、字幕PCの画面に出ます。字幕PCの画面を共有している場合は、
一瞬それが映ります。** クリップボードも字幕PCのものを使います。

失敗しても字幕は止まりません。結果はログに残ります。

### 6.4 Zoom側の設定

**ホストが AI Companion を使っている会議では、参加したときにダイアログが出ます**
（「AI Companionは有効です。」）。**Zoom側の設定では消せません。** 消す方法を
探さないでください。

**放っておいて構いません。** 誰も押さなくても字幕は出ます。無人で動かしていても
支障はありません。

以下は Windows ネイティブの話です。**Docker の場合、設定は済んでいます。**
コンテナを作るときに書き込んであるので、読み飛ばして構いません。要るのは
Zoom へのサインインだけです（2.6）。

Windows ネイティブで自動参加を使う場合は、Zoomクライアント側で**1回だけ**次を設定して
ください。毎回は要りません。

- 音声の出力先 `CABLE Input`、マイクはミュート（手順2と同じ）
- 参加時にマイクをミュート
- 参加時にビデオをオフ
- **「コンピューターオーディオに参加」の確認を出さない**

最後の1つが特に重要です。**この確認が出たままだと、参加はできても音が繋がりません。**
無人では誰も押せないので、原因の分かりにくい失敗になります。

会議に入れたのに音が来ない状態が5分続くと、操作画面に次のように出ます。

> Zoomから音が来ない。パスコード違いか、待機室で止まっているか、更新のダイアログが
> 出ている可能性がある。画面を見ること。

**個人リンク（`https://zoom.us/my/...`）は使えません。** 会議番号が入っていないためです。
番号入りの招待URL（`/j/...`）を使ってください。

**Zoomから出る手段は、クライアントを終了させることだけです。** 会議から出る操作を外から
指示する方法がないためです。**人が手で入った会議は終了させません。** 手で入っていた会議を
巻き添えにしないよう、LiveCaption が参加させたときだけ終了させます。

### 6.5 ホスト用URL

LiveCaption がホストでない会議でも、ホストに協力してもらえば Zoom字幕を出せます。

会議ごとに、参加者用とは**別の秘密のURL**を作れます。予定の入力欄の
**ホスト用URLを出す**を押すと表示されます。

**このURLはホストにだけ渡してください。** 参加者用のURLと取り違えないでください。
ホスト用URLを持つ人は、その会議の字幕をZoomへ流し込めます。

ホストがそのURLをブラウザで開くと、トークンを貼る画面が出ます。貼って送ると、
LiveCaption がZoomへ字幕を送り始めます。

**このURLは、経路が Tailscale のときだけ作られます。** Cloudflare では作りません。
TLS が Cloudflare 側で終わるので、Zoomの資格情報が Cloudflare を平文で通るためです。

受け付けるのは次の場合だけです。

- いま配信している会議であること
- 予定の前後30分か、その会議を動かしている間であること
- 1回だけ（2回目からは断ります。操作画面の「もう一度受け付ける」で開き直せます）

**URLが漏れたら、その会議を消して作り直してください。**

### 6.6 常駐と自動起動

**Docker の場合、何もしなくても常駐しています。** コンテナは `restart: unless-stopped`
で動いているので、落ちても、ホストを再起動しても、自分で戻ってきます。

**このため、操作画面の「アプリの再起動」は、止めるのではなく再起動になります。**
本当に止めるときは、ホストで次を実行します。

```sh
docker compose stop
```

止めたものは、ホストを再起動しても上がってきません。戻すのは `docker compose start`
です。**止めると操作画面も消えるので、外からは戻せません。** 遠隔で使っているときは
実行しないでください。

#### 会議のときだけ起こす場合

**常時起動しないノートPCでは、この常駐が邪魔になります。** Docker Desktop を
立ち上げるたびに LiveCaption が上がり、予定を入れてあれば Zoom にまで入ります。

`.env` に次を書くと、常駐しなくなります。

```
LIVECAPTION_RESTART=no
```

こうすると、会議のたびにホストで `docker compose up -d` を実行して起こし、
終わったら `docker compose down` で落とす使い方になります。

**操作画面のボタンの文字も変わります。** 常駐しているときは「アプリの再起動」、
常駐しないときは「アプリの終了」です。**押した結果がそのとおりになります。**

| `LIVECAPTION_RESTART` | 常駐 | ボタン | 押すと |
|---|---|---|---|
| `unless-stopped`（既定） | する | アプリの再起動 | 落ちて、数秒で戻ってきます |
| `no` | しない | アプリの終了 | 止まったままになります |

**`no` にしたときは、操作画面からは戻せません。** ホストで
`docker compose up -d` を実行してください。

以下は Windows ネイティブの話です。

`StartLiveCaptionTray.vbs` をダブルクリックすると、**ウィンドウを出さずに**タスクトレイへ
常駐します。

| アイコンの色 | 状態 |
|---|---|
| 青 | 待機中 |
| 緑 | 字幕を出している |
| 赤 | 失敗が残っている |

アイコンにマウスを乗せると、次の会議か、いま出している会議が出ます。右クリックすると、
操作画面・ログ・終了を選べます。

ウィンドウが無いので、ログは `local/log/` に残ります（20本まで）。

**`StartLiveCaptionTray.vbs` を編集するときは、ASCII だけで書いてください。**
Windows はこのファイルを UTF-8 として読みません。日本語のコメントを入れると、
**ダブルクリックしても何も起きません。エラーも出ません。** ファイルの冒頭にも
英語で注意書きがあります。

Windows のログオン時に自動で起動させるには、次を実行します。管理者権限は要りません。

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install_autostart.ps1
```

外すときは `-Remove` を付けます。

**字幕PCはログオンしたままにしてください。** 画面のロックは構いません。ログオフすると
LiveCaption は動けません。再起動のあとは、誰かがログオンするまで LiveCaption は上がりません。

## 7. 用語対訳表

専門用語をどれだけ正しく出せるかは、`etc/glossary/` の表で決まります。**主に保守するのは用語対訳表です。**

### 自分の分野の表の作成

**分野ごとに1ファイル置きます。** 置き場は `etc/glossary/` で、拡張子は `.tsv` です。

見本が [glossary-example.tsv](glossary-example.tsv) にあります。これを
`etc/glossary/` にコピーして、自分の会議に出る語に置き換えてください。

```powershell
copy docs\glossary-example.tsv etc\glossary\MyProject.tsv
```

**`etc/glossary/` は Git に入りません。** そのため、クローンした直後は表が1つも
ありません。人名や組織名を入れると表は効きますが、それを共有したくないためです。
表は各自の手元に残ります。

**Docker の場合は、`etc/glossary/` にファイルを置くのではなく、操作画面から
アップロードします**（設定タブ →「用語集」）。ボリュームの中に保存されるので、
コンテナを作り直しても消えません。ダウンロードと削除も同じ場所からできます。

分けておく理由は2つあります。1つは、会議に要らない語を外せることです。もう1つは、文字起こしに
渡せる語数に上限があることです（`config.ASR_KEYWORD_LIMIT`、既定 200）。1つの大きな表を全部の
会議で使うと、関係の無い語が上限を占めて、本当に要る語が渡らなくなります。

### 書式

1行に1語、3列をタブで区切ります。

```
日本語（正しい表記）  <TAB>  English  <TAB>  よくある誤認識（カンマ区切り）
```

この表は2か所で使います。

1. **文字起こし。** 日本語と英語の表記を、キーワードとして文字起こしのモデルに渡します。用語を正しく
   聞き取る確率が上がります
2. **翻訳。** 表全体を翻訳のプロンプトに入れ、第3列から置換規則を組み立てます

**効くのは第3列です。** 文字起こしはそれでも間違えます。実際に出た誤りを書いておくと、翻訳側が
そこから正しい用語を復元できます。

### 会議ごとの表の選択

操作画面の**設定**タブにある「用語集」の行は畳んであります。**いまどの表を使っているかは、畳んだままでも
見えます**（表の名前と合計の語数）。行を押すと一覧が開くので、使う表にチェックを
入れてください。**チェックした時点で切り替わります。**

表が8個以上になると、一覧の上に絞り込みの欄が出ます。**チェックを入れた表は、絞り込みで
他が消えても残ります。** 見えていない表のチェックを外せてしまうと、どの表を外したのか
分からなくなるためです。「全部選ぶ」「全部外す」は、絞り込みで隠れている表にも効きます。

チェックの下の行に、合計の語数と、文字起こしに渡す語の数が出ます。**上限に気をつけてください。**
`config.ASR_KEYWORD_LIMIT` を超えた語は文字起こしに届きません。上限を超えたときは語数が赤で表示されるので、表を
減らします。

**LiveCaption は表の選択を覚えています。** 次の起動も同じ組み合わせで始まります。起動時に決めることも
できます。

```powershell
pixi run caption --web --glossary 表の名前1 表の名前2
```

**同じ日本語が複数の表にあるときは、1つにまとめます。** 英語は最初に見つけた表のものを
使い、第3列の誤認識は全部の表から集めます。英語が食い違ったときは、食い違いを画面に出したうえで、最初の表の
ほうを使います。

### 会議後の表の更新

1. 会議の記録の `.md` を開きます（操作画面の「会議の記録」から落とせます）。冒頭に、
   その会議で使った表の名前が書いてあります
2. 訳が誤っている用語を探します
3. 元の誤った文字起こしを、その用語が載っている表の第3列に足します

第3列に入れるものは3種類あります。

- **同音の誤変換。** 例:「光軸」が「校則」になる
- **英語の誤認識。** 略語が普通の英単語に化ける。例: `PID` が「peed」になる
- **前の語の末尾が食い込んだ形。** 文字起こしは音の切れ目を誤ります。「この回折」が「子の解析」に
  なったなら、`回折` の行の第3列に「子の解析」を入れます。**前の語ごと入れてください。**
  文字起こしがそう書き起こすからです

**推測で入れないでください。** 意味の通らない語が残ったら、話していた人に聞きます。
音声だけから正解を当てられないことがあります。

**足したつもりの語が、実際には表に入っていないことがあります。** 列の区切りがタブで
なくスペースになっていると、行全体が1つの日本語の語として読まれ、**英語も誤認識も
登録されません。** 見た目では分かりません。

**足した語は、会議の前に実際に試してください。** その語を含む文を話して、字幕に
正しい英語が出るかを見ます。表に書いただけでは、効いている証拠になりません。

## 8. 会議の記録

**LiveCaption は既定で会議の記録を残します。** 何も指定しなくて構いません。

置き場は `local/transcripts/` です。Docker の場合はコンテナの中で、`state` ボリュームの
中に残ります。

```
local/transcripts/live-caption_2026-09-08_143012.jsonl   1文ごとに追記する
local/transcripts/live-caption_2026-09-08_143012.md      読める形。終了時に書く
```

### 記録のダウンロード

**記録は字幕の機体の中に溜まります。操作画面からダウンロードしてください。**
機体の前まで行ったり、遠隔操作でファイルを取り出したりする必要はありません。

操作画面の**この会議**タブ、「会議の記録」にボタンが2つあります。

| ボタン | 中身 |
|---|---|
| **読める形 (.md)** | 人が読む形。文字起こしと字幕が対になっています |
| **原本 (.jsonl)** | 1行が1文。遅延の実測も入っています。用語対訳表を育てるのはこちら |

保存先は、**操作画面を開いている端末**のダウンロードフォルダです。

**ダウンロードできるのは最新の1本だけです。** どれが対象かは、ボタンの下に出ています。
古い会議の記録が要るときは、`local/transcripts/` から直接取ってください。Docker の
場合は `docker compose cp` を使います。

```sh
docker compose cp engine:/app/local/transcripts ./transcripts
```

**会議の最中でもダウンロードできます。** そのときの `.md` には「会議はまだ続いている」と
書きます。

**「停止」を押すと、記録はそこで区切られます**（3秒ほど後）。`.md` が書かれ、
次の記録が始まります。**停止のあとに落とすと、終わった会議の記録が手に入ります。**
休憩で止めて、すぐ（3秒以内に）再開したときは区切りません。

### 置き場の変更

変える必要はありませんが、リポジトリの外に出したいときは（同期フォルダの中に
リポジトリを置いている場合など）、`.env` に書きます。

```
LIVECAPTION_SAVE_DIR=%LOCALAPPDATA%\LiveCaption\transcripts
```

**無いフォルダは LiveCaption が作ります。書き込めないフォルダは使わず、既定の置き場に落とします。**
起動のたびに変えたいときは `--save-dir` を使います。こちらは `.env` より優先します。

**Docker の場合は、既定のままで構いません。** 記録は `state` ボリュームの中に
書かれるので、コンテナを作り直しても消えません。**ホストのフォルダに出したいときは、
`.env` ではなく `compose.yml` のボリュームを足してください。** コンテナの中から見た
パスを `LIVECAPTION_SAVE_DIR` に書いても、ホストのフォルダにはなりません。

記録は溜まっていきます。**消すのは手作業です。** ホストから次のように消せます。

```sh
docker compose exec engine ls /app/local/transcripts
docker compose exec engine rm /app/local/transcripts/live-caption_2026-09-01_*
```

### 記録の中身

文字起こしと字幕が対になっています。時刻は**文字起こしが確定した時刻**です。

`.jsonl` には遅延の実測も入ります。`.md` には出ませんが、後から遅延の設定を調整するのに要ります。

| 項目 | 意味 |
|---|---|
| `cut` | 文が確定した理由。`punct`（文末記号）/ `force`（長さ）/ `idle`（無音）/ `flush`（終了時） |
| `waited` | 無音で確定したときに、実際に待った秒数 |
| `took` | 翻訳にかかった秒数 |
| `total` | **確定から最初の字幕までの秒数。** `total − took` が待ち行列 |
| `spec` | 先回りの翻訳が当たった文に付く。このとき `total` は `took` より小さくなる |
| `dir` | そのときの字幕の向き |

- **`.md` が書かれるのは、「停止」を押したときと、アプリを終了したときです。**
  電源ごと落ちたときは `pixi run python scripts/transcript_to_md.py` で
  `.jsonl` から作り直します（ダウンロードしたときの `.md` は、そのつど組み立てています）
- 記録を残したくないときは `--no-save` を付けて起動します
- 1文も出なかったときは、ファイルを残しません

## 9. コマンド一覧

### Docker

会議のために打つコマンドはありません。**以下は据え付けと保守で使うものです。**
リポジトリのフォルダの中で実行します。

```sh
docker compose up -d --build     # 作って起動する。最初の1回と、コードを直したあと
docker compose logs -f           # 起動の様子と、動いている間のログ
docker compose ps                # 動いているか
docker compose restart           # 入れ替えずに起こし直す
docker compose stop              # 止める。ホストを再起動しても上がってこない
docker compose start             # 止めたものを戻す

docker compose exec engine bash  # 中に入る
docker compose cp engine:/app/local/transcripts ./transcripts   # 記録を取り出す

# 録音した音で試す。Zoom へは何も送らない
docker compose run --rm -v "$PWD/録音:/samples:ro" engine \
  --from-file /samples/test.wav --dry-run
```

**`docker compose down -v` は使わないでください。** ボリュームまで消えるので、
会議の一覧も、閲覧URLも、Tailscale の署名も、Zoom のサインインも失われます。

### Windows ネイティブ

会議で使うのはバッチファイルです。以下に、バッチファイル以外の起動方法も並べます。

```powershell
StartLiveCaption.bat                             # 会議で使うのはこれ
StartLiveCaptionTray.vbs                         # 窓を出さずにタスクトレイへ常駐する
InstallToStartMenu.bat                           # スタートメニューに登録する（最初に1回）

pixi run web                                     # 同じもの。PowerShell から起動する場合
pixi run caption --web                           # 同上
pixi run caption --token "<URL>" --web           # Zoom字幕とブラウザ字幕の両方
pixi run caption --token "<URL>"                 # Zoom字幕だけ
pixi run caption --web --no-save                 # 記録を残さない
pixi run caption --check-audio 20                # 音量だけ見る（API不要）
pixi run devices                                 # 入力デバイスの一覧
pixi run caption --from-file recording.wav --dry-run   # WAVを実時間で流す
pixi run python scripts/transcript_to_md.py      # 落ちたあとに .md を作り直す
pixi run python scripts/cable_loopback.py        # VB-CABLE の経路を試す
```

オプション:

| オプション | 意味 |
|---|---|
| `--token <URL>` | Zoom字幕APIのトークン。あとから操作画面に貼っても構いません |
| `--direction <向き>` | 字幕の向き。`ja2en`（日本語の会議に英語字幕）か `en2ja`（英語の会議に日本語字幕）。既定は前回の選択 |
| `--glossary <名前> ...` | 使う用語集（`etc/glossary/` の .tsv の名前）。複数を重ねられます。既定は前回選んだ組み合わせ |
| `--device <名前>` | 入力デバイス名の一部。既定: `CABLE Output`。Docker では `pulse` を渡してあります |
| `--web [ポート]` | ブラウザに字幕を出します。閲覧側のポート、既定 8080 |
| `--control-port <ポート>` | 操作画面のポート、既定 8081 |
| `--control-bind [アドレス]` | **操作画面を tailnet からも開けるようにします。** 値を省くと自分で調べます。127.0.0.1 は必ず残ります。**Tailscale の範囲以外は受け付けません**（4.10 参照） |
| `--tray` | **タスクトレイに常駐します。** ログは `local/log/` にも残ります |
| `--web-bind <アドレス>` | **閲覧画面**が待ち受けるアドレス、既定 127.0.0.1。同じLANの端末から直接見せるなら 0.0.0.0。操作画面はこの設定の影響を受けません |
| `--tunnel` | 起動時からトンネルを張ります。既定では張りません |
| `--no-browser` | ブラウザを自動で開きません |
| `--no-save` | 会議の記録を残しません |
| `--save-dir <フォルダ>` | 記録の置き場。**`.env` の `LIVECAPTION_SAVE_DIR` より優先します。** 既定は `local/transcripts/` |
| `--dry-run` | Zoom には送らず、画面に出すだけ |
| `--from-file <wav>` | デバイスの代わりに WAV を実時間で流します。24 kHz モノラル |
| `--loop` | `--from-file` のファイルを繰り返します |
| `--delay <段階>` | 文字起こしの遅延と精度。`minimal`・`low`・`medium`・`high`・`xhigh`。既定 `low` |
| `--model <名前>` | 翻訳のモデル。既定 `gpt-4.1-mini` |
| `--check-audio [秒]` | 音量を表示して終わります。API を呼びません |
| `--list-devices` | 入力デバイスの一覧を出します |
| `--cloudflared <パス>` | `cloudflared` の場所。PATH か `local/bin` にあれば要りません |

自動起動の登録と解除:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install_autostart.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install_autostart.ps1 -Remove
```

**ポートが埋まっているときは、両方の番号を変えてください。** 8081 は操作画面のものなので、
閲覧側に 8081 を指定してはいけません。

```powershell
pixi run caption --web 8090 --control-port 8091
```

## 10. 設定

設定は `src/live_caption/config.py` にあります。既定値は実測で決めたものなので、理由があるときだけ
変えてください。

**下の4つは、操作画面と `.env` の両方から変えられます。** コードを直す必要はありません。

### 操作画面からの変更

**設定**タブの「遅延の調整」の行を押すと、入力欄が開きます。**よく変えるものではないので
畳んであります。**

- 数字を直して欄から離れると、**その場で効きます。再起動は要りません**
- **`.env` に保存** を押すと、次の起動でも同じ値で始まります。`.env` の他の行
  （`OPENAI_API_KEY` など）は消えません
- **既定に戻す** で実測で決めた値へ戻ります
- 既定と違う値があるときは、畳んだままでも見出しに「N 個を既定から変えている」と出ます

### `.env` への直接記述

書き方は `.env.example` にあります。

| `.env` の名前 | 対応する設定 |
|---|---|
| `LIVECAPTION_IDLE_FLUSH_SEC` | `IDLE_FLUSH_SEC` |
| `LIVECAPTION_SPECULATE_AFTER_SEC` | `SPECULATE_AFTER_SEC` |
| `LIVECAPTION_FORCE_CUT_CHARS` | `FORCE_CUT_CHARS` |
| `LIVECAPTION_LINE_INTERVAL_SEC` | `LINE_INTERVAL_SEC` |

差し替えると、起動時に `[設定] .env で差し替えた: …` と出ます。

**`IDLE_FLUSH_SEC` だけを変えると、`SPECULATE_AFTER_SEC` も自動で追随します**
（`IDLE_FLUSH_SEC − 1.1` 秒）。合わせないと、先回りの翻訳が早すぎて、捨てる翻訳が増えるだけに
なります。

**書き間違えても会議は止まりません。** 数字として読めない値や小さすぎる値を書いたときは、警告を出して
既定値のまま動きます。ただし**黙って無視はしません**ので、起動時の表示を見てください。

### 主な設定

| 設定 | 既定 | 意味 |
|---|---|---|
| `ASR_MODEL` | `gpt-live-transcribe` | 文字起こしのモデル |
| `ASR_DELAY` | `low` | `minimal`・`low`・`high` を比べたところ、`minimal` と `high` はどちらも専門用語を取り違えました |
| `ASR_LANGUAGES` | `("ja", "en")` | **言語を1つに固定してはいけません。** 会議の途中で言語が切り替わることがあります |
| `ASR_KEYWORD_LIMIT` | 200 | 文字起こしに渡す用語の数の上限。**表の語数より大きくしておいてください。** 切り捨てが起きたら起動時に警告が出ます |
| `TRANSLATE_MODEL` | `gpt-4.1-mini` | 翻訳のモデル |
| `CONTEXT_SENTENCES` | 3 | 翻訳に文脈として渡す直前の文の数 |
| `MAX_CAPTION_CHARS` | 80 / 40 | 字幕1行の最大文字数。向きで変わります（英語80、日本語40） |
| `FORCE_CUT_CHARS` | 70 / 140 | これより長い文は強制的に切ります。向きで変わります（日本語を聞くとき70、英語140）。字幕が速すぎるなら下げてください |
| `IDLE_FLUSH_SEC` | 2.5 | 発話が途切れてから、文末記号が無くても確定させるまでの秒数。**下げる前に `stream_test.py` で delta の間隔を測ってください。** 話し続けている間の間隔より短くすると、喋っている途中で文を切ります |
| `IDLE_POLL_SEC` | 0.1 | 上のタイマーを見にいく間隔。細かいほど無駄な待ちが減ります |
| `SPECULATE_AFTER_SEC` | 1.4 | 無音がこれだけ続いたら、確定を待たずに翻訳を投げます。当たれば字幕が約0.9秒早く出ます。外れた分は捨てるので料金が増えます。`0` にすると先回りを止めます |
| `LINE_INTERVAL_SEC` | 0.6 | Zoom へ1行ずつ送る間隔。字幕の表示領域が最小4行しかないので、まとめて送ると先頭が押し出されます。**閲覧画面には効きません**（全行すぐ出ます） |
| `WEB_LINES` | 8 | 閲覧画面に出す行数 |
| `WEB_PORT` | 8080 | 閲覧画面 |
| `CONTROL_PORT` | 8081 | 操作画面 |

## 11. トラブルシューティング

| 症状 | 見るところ |
|---|---|
| 何も起きない。ログが流れない | **「いまの状態」の開始を押しましたか。** 起動しただけでは動きません |
| `CABLE Output` が一覧に無い | VB-CABLE を入れましたか。PC を再起動しましたか |
| 音量メーターが振れない | 会議ソフトのスピーカー設定。両方 48000 Hz か。**設定タブの「音声の入力」が `CABLE Output` か** |
| 「入力を開けない」と出る | 別のアプリが専有していないか。48000 Hz を受け付けるデバイスか。別の入力を選んでください |
| 文字起こしの行が出ない | `.env` の `OPENAI_API_KEY`。**`.env` はリポジトリ直下（`pixi.toml` と同じ場所）にありますか。名前が `.env.txt` になっていませんか。** ネットワークも確認 |
| 文字起こしは出るが字幕が出ない | 翻訳のエラーが画面に出ているはずです |
| ログは流れるが受信側に出ない | **ホストの画面を見ていませんか**（ホストには出ません）。相手が手動字幕をオンにしたか。トークンが今の会議のものか |
| 喋ると別の字幕が出る | **会議ソフトの自動字幕が動いています。** オフにしてください |
| 表にあるのに用語を外す | `ASR_KEYWORD_LIMIT` で切られていないか。表の末尾は文字起こしに渡りません |
| ある分野の用語がまとめて外れる | その分野の表にチェックが入っていません |
| 字幕が途中で止まった | `seq` が巻き戻りました。アプリを再起動したなら `local/seq_state.json` を確認してください |
| 字幕が速すぎて読めない | 受信側に表示領域を広げてもらいます。`config.FORCE_CUT_CHARS` を下げてください |
| 文字起こしの再接続が増える | 回線です。字幕PCの会議ソフトで受信ビデオを止め、別回線を試してください |
| 遠隔操作したら字幕が止まった | **RDP で入っていませんか。** 音声経路が切れます（4.9 を見てください） |
| 予定の時刻になっても始まらない | **「この会議を自動で開始する」に印が付いていますか。** 既定は切りです。「いまの状態」に予定が並んでいるかも確認してください |
| Zoomに入ったのに音が来ない | **「コンピューターオーディオに参加」の確認が出たままになっていませんか**（6.4）。待機室で止まっている、パスコードが違う、という可能性もあります |
| 会議に入ると AI Companion のダイアログが出る | **放っておいて構いません**（6.4）。誰も押さなくても字幕は出ます。Zoom側の設定では消せません |
| 会議が終わっても離脱しない | 無音で終了するまでの分を確認してください。安全上限に達すれば必ず止まります |
| 会議が早く終わったのに動き続ける | 誰かのマイクが開いたままだと、音が続くので無音になりません。「いま止める」を押してください |
| 自動起動しない | ログオンしていますか。**ログオフしていると動けません。** タスクスケジューラで `LiveCaption` の状態を見てください |
| トレイのアイコンが出ない | ログ（`local/log/`）を見てください。窓が無いので、そこが唯一の手がかりです |
| tailnet から操作画面が開けない | `--control-bind` を付けて起動しましたか。Tailscale が上がっていますか。ACL で塞いでいませんか |

**Docker で動かしている場合:**

| 症状 | 見るところ |
|---|---|
| 操作画面が開かない | `docker compose ps` でコンテナが動いていますか。`docker compose logs` に Tailscale のアドレスが出ていますか。**`https://` は完全な名前で開いてください**（短い名前やIPでは証明書が合いません） |
| ログに認証のURLが出たまま | `TS_AUTHKEY` が無いときの動きです。URLをブラウザで開いて承認してください |
| tailnet に入ったのに他のノードと話せない | **Tailnet Lock です。** 署名されていません。`tailscale lock status` でノード鍵を見て、署名鍵を持つ機体で署名してください（2.3） |
| 配信を開始できない | ACL の `nodeAttrs` に `funnel` が入っていますか。タグを付けると `autogroup:member` から外れ、`nodeAttrs` が無いと Funnel を失います（2.3） |
| コンテナを動かすとホストの通信が切れる | **ConnMan です**（3.2。Linux のみ）。数十秒遅れて壊れるので、起動直後に確かめても分かりません |
| Zoom に入れない | サインインが切れていませんか。**VNC を起動して Zoom の窓を見てください**（2.6）。待機室で止まっていることもあります |
| 用語集が空のまま | このリポジトリに表は入っていません（2.7）。操作画面からアップロードしてください |
| 会議の記録が見当たらない | ボリュームの中にあります。操作画面からダウンロードするのが早いです |
| 「アプリの再起動」を押したのに止まらない | `restart: unless-stopped` の動きです。本当に止めるなら `docker compose stop`（6.6） |

**受信側を先に確かめてください。** 送信が成功しても、受信側に字幕が表示されているとは限りません。
送信が全て HTTP 200（成功）なのに受信側に何も出ていない、ということが実際に起きます。原因は受信側に
あります。

**字幕は時間では消えません。** 新しい行に押し出されるまで残っています。見逃しても、
送り直さずにもう一度見れば済みます。

## 12. 仕組み

ここから先の説明は、LiveCaption を使うだけなら読まなくて構いません。

### 別の参加者として入る理由

**Docker の場合:**

```
[ホストPC]        通常どおり会議を進める
     |
[コンテナ]
  Zoom ---------- 無言の参加者として参加、マイクはミュート
   |
   +-- 出力 --> meeting（PulseAudio の仮想の出口）
                    |
                 meeting.monitor --> LiveCaption
                                       |-- 文字起こし
                                       |-- 翻訳
                                       +-- 出力
```

**Windows ネイティブの場合:**

```
[ホストPC]        通常どおり会議を進める
     |
[字幕PC]
  会議ソフト ----- 無言の参加者として参加、マイクはミュート
   |
   +-- スピーカー出力 --> CABLE Input
                             |   (VB-CABLE、仮想オーディオケーブル)
                          CABLE Output --> LiveCaption
                                             |-- 文字起こし
                                             |-- 翻訳
                                             +-- 出力
```

**LiveCaption を、Zoomのホストの PC で動かしてはいけません。** 会議ソフトは自分のマイク音声を
自分のスピーカーに流しません。その PC でスピーカー出力を録ると、**ホスト自身の声が入りません。**
別の参加者として入れば、会議ソフトからミックス音声を受け取るので、その中に全参加者の
声が入っています。

**音は仮想の音声装置を通します。** ループバックの API を使わないので、音量やミュートの
影響を受けません。Docker では PulseAudio の null sink が、Windows では VB-CABLE が
その役です。**Docker のほうは、ホストの音声装置をまったく使いません。** ホストで音楽を
鳴らしても字幕には入りませんし、ホストに音声装置が無くても動きます。

### 用語対応の2段構成

LiveCaption は、専門用語を正しく出すために、文字起こしだけに頼りません。

1. **文字起こし側。** 用語対訳表の語をキーワードとして渡し、固有名詞の音を拾わせます
2. **翻訳側。** 用語対訳表と、実際に出た誤認識からの置換規則と、直前3文の文脈を
   モデルに渡します。**ここが本命です**

文字起こし側が音の近い誤りをしても、文脈と用語対訳表があれば翻訳側で復元できます。
**ただし全部は直せません。** 誤認識が別の妥当な専門用語になると、流暢な誤訳が
出ます。

### 確定した文だけを送る理由

途中経過を出して後から書き換えると、読み手は追えません。字幕は蓄積されて置き換わらないので、
途中経過を送ると、その途中経過が1行として残り、訂正した完成版がその下に並びます。
**読み手には同じ内容が2回見えます。**

このため、LiveCaption は翻訳にかかる時間をストリーミングで隠せません。

### 遅延

遅延は文の終わり方で変わります（実測）。

| | 文字起こし | 確定待ち | 翻訳 | 送信 | 合計 |
|---|---|---|---|---|---|
| 文末記号で終わった文（約74%） | 0.2〜1秒 | 0秒 | 0.9秒 | 0.3秒 | **約1.5〜2秒** |
| 無音で終わった文（約9%） | 同上 | 2.5秒 | 0.9秒 | 0.3秒 | **約4秒** |
| 長すぎて強制的に切った文（残りの約17%） | 同上 | 0秒 | 0.9秒 | 0.3秒 | **約1.5〜2秒** |

強制的に切った文とは、文末記号が来ないまま長くなった文です。確定を待たないので、
遅延は文末記号で終わった文と同じです。

無音で終わった文は、確定を待つ間に先回りで訳しておきます（`SPECULATE_AFTER_SEC`）。
当たれば翻訳の 0.9秒 が消えます。

**確定待ちは下げられません。** 文字起こしの出力が途切れる間隔を測ると、話し続けている最中でも
2.5秒 近く空くことがあります。閾値を下げると、喋っている途中で文を切る回数が増えます。
