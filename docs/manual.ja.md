# LiveCaption マニュアル

The English version is [manual.md](manual.md).

LiveCaption は、日本語で行われる会議にリアルタイムの英語字幕を出す。
会議の音声を聞き、日本語を認識し、英語に翻訳して、必要な人に見せる。

KAGRA の会議のために作った。日本語を話さない参加者が数人いて、
残りは日本語で話す、という会議である。

**Zoom 専用ではない。** 音声は仮想オーディオケーブルから取るので、
音が出る会議ソフトなら何でも使える。

---

## 1. 仕組み

Windows PC を1台、字幕専用にする。その PC は会議に無言の参加者として入る。
マイクはミュートしたままにする。

```
[ホストPC]        通常どおり会議を進める
     |
[字幕PC]
  Zoom ----- 無言の参加者として参加、マイクはミュート
   |
   +-- スピーカー出力 --> CABLE Input
                             |   (VB-CABLE、仮想オーディオケーブル)
                          CABLE Output --> LiveCaption
                                             |-- 音声認識
                                             |-- 翻訳
                                             +-- 出力（下を見ること）
```

**専用 PC を使うこと。ホスト PC で動かしてはいけない。**
Zoom は自分のマイク音声を自分のスピーカーに流さない。ホスト PC で
スピーカー出力を録ると、ホスト自身の声が入らない。字幕 PC は Zoom から
ミックス音声を受け取るので、その中に全参加者の声が入っている。

### 字幕の出口は3つある

3つとも同時に使える。

| 出口 | ホスト権限 | 見せ方 | 外に出るか |
|---|---|---|---|
| Zoom字幕API | **要る** | 各自が「字幕を表示」をオンにする | Zoom経由 |
| 画面共有 | 要らない | 閲覧画面を全画面にして共有する | **出ない** |
| URL配布 | 要らない | 各自の端末でURLを開く | Cloudflare経由 |

### 遅延

文の終わり方で変わる（2026-09-09 の実測）。

| | 認識 | 確定待ち | 翻訳 | 送信 | 合計 |
|---|---|---|---|---|---|
| 文末記号で終わった文（約74%） | 0.2〜1秒 | 0秒 | 0.9秒 | 0.3秒 | **約1.5〜2秒** |
| 無音で終わった文（約9%） | 同上 | 2.5秒 | 0.9秒 | 0.3秒 | **約4秒** |

無音で終わった文は、確定を待つ間に先回りで訳しておく
（`SPECULATE_AFTER_SEC`）。当たれば翻訳の 0.9秒 が消える。

## 2. 必要なもの

| 品目 | 補足 |
|---|---|
| Windows PC 1台 | 字幕専用。GPU は要らない。メモリ 32 GB あれば十分すぎる |
| VB-CABLE | 無料の仮想オーディオケーブル。[vb-audio.com/Cable/](https://vb-audio.com/Cable/) |

## 3. 導入

字幕 PC で一度だけ行う。

### 3.1 VB-CABLE を入れる

[vb-audio.com/Cable/](https://vb-audio.com/Cable/) からダウンロードする。
**インストーラは管理者権限で実行し、終わったら PC を再起動する。**

### 3.2 CABLE の両方を 48000 Hz にする

再起動後、Windows のサウンド設定で次の2つを確認する。

| デバイス | 形式 |
|---|---|
| `CABLE Input`（再生） | **48000 Hz**、16ビット |
| `CABLE Output`（録音） | **48000 Hz**、16ビット |

**両方を 48000 Hz に揃えること。** 食い違うと Windows が再サンプリングを行い、
音が乱れる。LiveCaption は 48000 Hz で開いて、自分で 24000 Hz に落とす。

### 3.3 プロジェクトを置く

```bash
cd C:\Users\Yoichi\Dropbox\src\projects\LiveCaption
pixi install
```

### 3.4 APIキーを `.env` に書く

`.env.example` を `.env` にコピーして、キーを埋める。

```
OPENAI_API_KEY=sk-...
```

**`.env` の値が、同じ名前の環境変数より優先される。**
両方に書いた場合、使われるのは `.env` のほうである。

### 3.5 字幕PCの Zoom を設定する

- 表示名を `Live Captions (EN)` などにする。参加者一覧に出るので、
  この PC が何をしているか分かるようにする
- スピーカー: **`CABLE Input`**
- マイク: **ミュート**。この PC は発言しない
- 「ビデオなしの参加者を非表示」にすると帯域が浮く

### 3.6 音声の経路を確かめる

この試験に会議も APIキーも要らない。`CABLE Input` にサイン波を流しながら、
`CABLE Output` から読み返す。

```bash
pixi run python scripts/cable_loopback.py
```

送った振幅が返ってくれば、VB-CABLE は正常である。

```
--- 本体が既定で選ぶもの: 2 'CABLE Output (VB-Audio Virtual ' [MME] ---
  区間 39、音あり 39（100%）  最大 peak 0.299  取りこぼし 0
  => 通っている
```

### 3.7 スタートメニューに登録する（任意）

**`InstallToStartMenu.bat`** をダブルクリックする。現在のユーザーのスタート
メニューに `LiveCaption` の項目が入る。会議の前にこのフォルダを探さなくてよい。

```
Windowsキー  ->  「livecaption」と打つ  ->  Enter
```

目に入る場所に置きたければ、スタートメニューの LiveCaption を右クリックして
**スタートにピン留めする** か **タスクバーにピン留めする** を選ぶ。

管理者権限は要らない。作られるのはショートカット1つで、置き場所は
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\LiveCaption.lnk`。

**このフォルダを移動・改名したら、もう一度実行すること。** ショートカットは
絶対パスを持っているので、フォルダが動くと動かなくなる。

アイコンは `etc/LiveCaption.ico` を使う。変えるときは `scripts/make_icon.py` を
直して実行し、登録し直す。

登録を消すときは、端末から `-Remove` を付けて実行する。

```bash
InstallToStartMenu.bat -Remove
```

## 4. 会議で使う

### 手順1. アプリを起動する

**`StartLiveCaption.bat`** をダブルクリックする。手順3.7で登録してあれば、
スタートメニューの **LiveCaption** からでもよい。操作画面がブラウザで開く。

```
http://localhost:8081              操作画面   <- この画面は共有しないこと
http://localhost:8080/v/<ランダム>  閲覧画面   <- 共有するのはこちら
```

**操作画面を絶対に画面共有しないこと。** Zoom の字幕トークンが映っている。

**LiveCaption は、字幕の生成を止めた状態で始まる。** **開始**を押すまで、
音は取り込まれず、API も呼ばれない。会議に入る前に立ち上げてよい。
準備中の雑談は認識に流れない。

### 手順2. 字幕PCから会議に参加する

Zoom のスピーカーを `CABLE Input` にして、マイクをミュートする。

### 手順3. 入力デバイスを確かめる

操作画面の「音声の入力」を見る。`CABLE Output` になっているはずである。
違っていたら一覧から選ぶ。**選んだ時点で切り替わる。適用ボタンは無い。**
さっき挿した装置が一覧に無ければ「一覧を更新」を押す。

一覧には名前だけでなくホストAPIも出る。Windows では `CABLE Output` が
MME・DirectSound・WASAPI の3つに現れるためである。

```
2: CABLE Output (VB-Audio Virtual （MME、16 ch）
```

3つのどれでも動く。既定は MME で、それでよい。

### 手順4. 字幕の生成を開始する

「字幕の生成」の**開始**を押す。

**音量メーターを見ること。** 誰も喋っていなければメーターは振れない。
誰かに喋ってもらう。人が喋っているのにメーターが動かないなら、入力デバイスが
違う。別のものを選ぶ。**生成中でも差し替えられる。**

### 手順5. 字幕を見せる

下の3つから、1つ以上を選ぶ。

#### A. Zoom字幕API（ホストまたは共同ホストの権限が要る）

トークンは会議中にしか作れない。作れるのはホストと共同ホストだけである。

1. ホストがツールバーの「字幕」の横の矢印を押し、
   **「APIトークンをコピー」**を選ぶ
2. ホストがそのトークンを、会議のチャットで字幕PCに送る
3. 操作画面の「Zoom字幕」の「APIトークン」にトークンを貼って**登録**を押す。
   入力欄は伏せ字で、登録すると空になる
4. **開始**を押す。まず捨て字幕が3つ流れる

**Zoom の自動字幕をオフにすること。** Zoom の自動字幕と LiveCaption の字幕は、
同じ4行の窓を共有する。自動字幕が流れ続けると、LiveCaption の行は
窓の外へ押し出される。

**操作画面の右上の表示を見ること。**

| 表示 | 意味 |
|---|---|
| `Zoom: 未登録` | トークンがまだ入っていない |
| `Zoom: 停止中` | 登録済み。「開始」を押せば送る |
| `Zoom: 送信中` | 送っている |
| `Zoom: 送信中（失敗 3）` | **送信が失敗している。** トークンが切れたか、会議が変わった |
| `生成: 停止中` | **字幕を作っていない。** Zoom を送信中にしても1行も流れない |
| `生成: 中` | 字幕を作っている |

**失敗の数を見逃さないこと。** Zoom は間違ったトークンに 200 以外を返すだけで、
理由を教えない。トークンを取り直して登録し直す。

#### B. 画面共有

ホスト権限が要らず、字幕が外に出ない。

1. 操作画面の「画面共有で見せる」の**閲覧画面を開く**を押す
2. **F11** で閲覧画面を全画面にする
3. Zoom でそのブラウザの画面を共有する

**画面共有の映像は圧縮される。** 小さい字は潰れる。共有を始めた後、
2台目の端末から読めるかどうか確かめること。読めなければ行数を減らす
（`config.WEB_LINES`）。

#### C. URLを配る

これもホスト権限が要らない。Cloudflare を通る一時トンネルを開き、
公開URLとQRコードを作る。

1. 操作画面の「参加者への配信」の**トンネルを開始**を押す。
   表示が `配信: 起動中…` から `配信: 中` に変わる
2. 字幕を見たい人にQRコードを見せるか、URLを送る
3. 各自が自分のスマホやノートで開く

**トンネルは既定では張らない。** 字幕は Cloudflare を通るので、
未公開の観測結果を扱う会議では使わないこと。画面共有を使う。

### 手順6. 参加者に伝える

会議の冒頭で、字幕を読む人に次を伝える。

- Zoom の「字幕を表示」をオンにすること
- **字幕の表示領域をドラッグして広げること。** 既定は4行である。
  4行では翻訳を読む余裕がない

### 手順7. 終了する

操作画面の「アプリの終了」の**終了**を押す。ブラウザのタブもターミナルの窓も閉じる。

## 5. 会議の記録

**LiveCaption は既定で会議の記録を残す。** 何も指定しなくてよい。

置き場は**ユーザーのダウンロードフォルダ**である。

```
ダウンロード/live-caption_2026-09-08_143012.jsonl   1文ごとに追記する
ダウンロード/live-caption_2026-09-08_143012.md      読める形。終了時に書く
```

日本語の認識文と英語の字幕が対になっている。時刻は**認識が確定した時刻**である。

`.jsonl` には遅延の実測も入る。`.md` には出ないが、後から調整するのに要る。

| 項目 | 意味 |
|---|---|
| `cut` | 文が確定した理由。`punct`（文末記号）/ `force`（長さ）/ `idle`（無音）/ `flush`（終了時） |
| `waited` | 無音で確定したときに、実際に待った秒数 |
| `took` | 翻訳にかかった秒数 |
| `total` | **確定から最初の字幕までの秒数。** `total − took` が待ち行列 |
| `spec` | 先回りの翻訳が当たった文に付く。このとき `total` は `took` より小さくなる |

- 会議中に読みたければ、操作画面の「会議の記録」の**途中まで読む**を押す
- **`.md` が書かれるのは終了時である。** 電源ごと落ちたときは
  `pixi run python scripts/transcript_to_md.py` で `.jsonl` から作り直す
- 記録を残したくないときは `--no-save` を付けて起動する
- 置き場を変えるなら `--save-dir`
- 1文も出なかったときは、ファイルを残さない

## 6. 用語対訳表

専門用語の出来は `etc/glossary/` の表で決まる。**保守するのは主にこれらである。**

### 会議に合わせて表を選ぶ

**分野ごとに1ファイルあり、どれを使うかを選ぶ。** 置き場は `etc/glossary/` である。
`docs/` ではない。**読み物ではなく、アプリが読むデータだからである。**

| ファイル | 語数 | いつ使うか |
|---|---|---|
| `KAGRA_basic.tsv` | 23 | **常に。** 人名・組織・施設・防振・真空・低温 |
| `Interferometer.tsv` | 45 | 鏡・光学・長さの自由度の話が出る会議 |
| `LVK.tsv` | 0 | 空。LVK共同観測の用語が要るときに書く |

`KAGRA_basic` だけなら認識に渡す語は 41。`Interferometer` を足すと 124。上限は 200。

操作画面の「用語集」の行は畳んである。**いま何を使っているかは、畳んだままでも見える**
（表の名前と合計の語数）。行を押すと一覧が開くので、使う表にチェックを入れる。
**チェックした時点で切り替わる。**

一覧はその中で送るので、表がいくつあっても、下の設定が画面の外へ押し出されない。
表が8個以上になると、一覧の上に絞り込みの欄が出る。
**チェックを入れた表は、絞り込みで他が消えても残る。** 見えていない物のチェックを
外せてしまうと、何を外したのか分からなくなるためである。
「全部選ぶ」「全部外す」で一度に全部を変えられる。
**どちらも、絞り込みで隠れている表にも効く。** 生成中なら、新しい keywords を届けるために
認識を繋ぎ直す。

チェックの下の行に、合計の語数と、認識に渡す語の数が出る。
**上限に気をつけること。** `config.ASR_KEYWORD_LIMIT` を超えた語は認識に届かない。
超えたときは赤で出るので、表を減らす。

**選択は覚えている。** 次の起動も同じ組み合わせで始まる。起動時の画面と
操作画面の両方に出るので、何を使っているかは目で見て分かる。

起動時に決めることもできる。

```bash
pixi run caption --web --glossary KAGRA_basic Interferometer
```

**同じ日本語が複数の表にあるときは、1つにまとめる。** 英語は最初に見つけた表の
ものを使い、第3列の誤認識は全部の表から集める。英語が食い違ったら画面に出して、
最初の表のほうを使う。

### 書式

1行に1語、3列をタブで区切る。

```
日本語（正しい表記）  <TAB>  English  <TAB>  よくある誤認識（カンマ区切り）
```

この表は2か所で使う。

1. **認識。** 日本語と英語の表記を、キーワードとして認識モデルに渡す。
   用語を正しく聞き取る確率が上がる
2. **翻訳。** 表全体を翻訳のプロンプトに入れ、第3列から置換規則を組み立てる

**第3列が本体である。** 認識はそれでも間違える。実際に出た誤りを書いておくと、
翻訳の段がそこから正しい用語を復元できる。

会議のあとで表を育てる手順:

1. ダウンロードフォルダの `live-caption_*.md` を開く。冒頭に、その会議で
   使った表の名前が書いてある
2. 英語が誤っている用語を探す
3. 元の誤った日本語を、その用語が載っている表の第3列に足す
4. **英語の誤認識も入れる。** 例: `p-pol` に対する「people」
5. **前の語の末尾が食い込んだ形も入れる。**
   例: `干渉計` に対する「無観測系」。頭の「む」は前の語の音である

**推測で入れないこと。** 意味の通らない語が残ったら、話していた人に聞く。
「people parkour」は `p-pol` だった。音声からは誰も推測できなかった。

**足したつもりの語が入っているとは限らない。** 2026-09-08 に、`牛場` の行に
`Woza` が無いのを見つけた。メモには書いてあったのに、表には無かった。
判定に使う語は、実際に翻訳段へ通して確かめること。

**新しい語は、それが属する表に入れる。** どのKAGRAの会議でも出る語は
`KAGRA_basic`。鏡の制御の会議でしか出ない語は `Interferometer`。
分けておくことで、その会議に要らない語を外せる。

## 7. コマンド一覧

会議で使うのはバッチファイルである。以下はそれ以外の用途。

```bash
StartLiveCaption.bat                             # 会議で使うのはこれ
InstallToStartMenu.bat                           # スタートメニューに登録する（最初に1回）

pixi run web                                     # 同じもの。端末から起動する場合
pixi run caption --web                           # 同上
pixi run caption --token "<URL>" --web           # Zoom字幕とブラウザ字幕の両方
pixi run caption --token "<URL>"                 # Zoom字幕だけ
pixi run caption --web --no-save                 # 記録を残さない
pixi run caption --check-audio 20                # 音量だけ見る（API不要）
pixi run devices                                 # 入力デバイスの一覧
pixi run caption --from-file recording.wav --dry-run   # WAVを実時間で流す
pixi run python scripts/transcript_to_md.py      # 落ちたあとに .md を作り直す
pixi run python scripts/cable_loopback.py        # VB-CABLE の経路を試す
```

オプション:

| オプション | 意味 |
|---|---|
| `--token <URL>` | Zoom字幕APIのトークン。あとから操作画面に貼ってもよい |
| `--device <名前>` | 入力デバイス名の一部。既定: `CABLE Output` |
| `--web [ポート]` | ブラウザに字幕を出す。閲覧側のポート、既定 8080 |
| `--control-port <ポート>` | 操作画面のポート、既定 8081。**常に 127.0.0.1 でしか待ち受けない** |
| `--web-bind <アドレス>` | **閲覧画面**が待ち受けるアドレス、既定 127.0.0.1。同じLANの端末から直接見せるなら 0.0.0.0。操作画面はこの設定の影響を受けない |
| `--tunnel` | 起動時からトンネルを張る。既定では張らない |
| `--no-browser` | ブラウザを自動で開かない |
| `--no-save` | 会議の記録を残さない |
| `--save-dir <フォルダ>` | 記録の置き場。既定はダウンロードフォルダ |
| `--dry-run` | Zoom には送らず、画面に出すだけ |
| `--from-file <wav>` | デバイスの代わりに WAV を実時間で流す。24 kHz モノラル |
| `--loop` | `--from-file` のファイルを繰り返す |
| `--delay <段階>` | 認識の遅延と精度。`minimal`・`low`・`medium`・`high`・`xhigh`。既定 `low` |
| `--model <名前>` | 翻訳のモデル。既定 `gpt-4.1-mini` |
| `--glossary <名前> ...` | 使う用語集（`etc/glossary/` の .tsv の名前）。複数を重ねられる。既定は前回選んだ組み合わせ |
| `--check-audio [秒]` | 音量を表示して終わる。API を呼ばない |
| `--list-devices` | 入力デバイスの一覧を出す |
| `--cloudflared <パス>` | `cloudflared` の場所。PATH か `local/bin` にあれば要らない |

**ポートが埋まっているときは、両方の番号を変えること。**
8081 は操作画面のものなので、閲覧側に 8081 を指定してはいけない。

```bash
pixi run caption --web 8090 --control-port 8091
```

## 8. 設定

`src/live_caption/config.py` にある。既定値は実測で決めたものなので、
理由があるときだけ変えること。

**下の4つは、操作画面と `.env` の両方から変えられる。** コードを直さなくてよい。

### 操作画面から変える

「遅延の調整」の行を押すと開く。**よく変えるものではないので畳んである。**

- 数字を直して欄から離れると、**その場で効く。再起動は要らない**
- **`.env` に保存** を押すと、次の起動でも同じ値で始まる。
  `.env` の他の行（`OPENAI_API_KEY` など）は消えない
- **既定に戻す** で実測で決めた値へ戻る
- 既定と違う値があるときは、畳んだままでも見出しに「N 個を既定から変えている」と出る

### `.env` に直接書く

書き方は `.env.example` にある。

| `.env` の名前 | 対応する設定 |
|---|---|
| `LIVECAPTION_IDLE_FLUSH_SEC` | `IDLE_FLUSH_SEC` |
| `LIVECAPTION_SPECULATE_AFTER_SEC` | `SPECULATE_AFTER_SEC` |
| `LIVECAPTION_FORCE_CUT_CHARS` | `FORCE_CUT_CHARS` |
| `LIVECAPTION_LINE_INTERVAL_SEC` | `LINE_INTERVAL_SEC` |

差し替えると、起動時に `[設定] .env で差し替えた: …` と出る。

**`IDLE_FLUSH_SEC` だけを変えると、`SPECULATE_AFTER_SEC` も自動で追随する**
（`IDLE_FLUSH_SEC − 1.1` 秒）。合わせないと、先回りが早すぎて投げ捨てが増えるだけになる。

**書き間違えても会議は止まらない。** 数字として読めない値や小さすぎる値は、
警告を出して既定値のまま動く。ただし**黙って無視はしない**ので、起動時の表示を見ること。

| 設定 | 既定 | 意味 |
|---|---|---|
| `ASR_MODEL` | `gpt-live-transcribe` | 音声認識のモデル |
| `ASR_DELAY` | `low` | `minimal` と `high` はどちらも用語を外した |
| `ASR_LANGUAGES` | `("ja", "en")` | KAGRA の朝礼は前半が英語、後半が日本語。言語を固定してはいけない |
| `ASR_KEYWORD_LIMIT` | 200 | 認識に渡す用語の数の上限。**表の語数より大きくしておくこと。** 切り捨てが起きたら起動時に警告が出る |
| `TRANSLATE_MODEL` | `gpt-4.1-mini` | 翻訳のモデル |
| `CONTEXT_SENTENCES` | 3 | 翻訳に文脈として渡す直前の文の数 |
| `MAX_CAPTION_CHARS` | 80 | Zoom に送る英語1行の最大文字数 |
| `FORCE_CUT_CHARS` | 70 | これより長い日本語の文は強制的に切る。字幕が速すぎるなら下げる |
| `IDLE_FLUSH_SEC` | 2.5 | 発話が途切れてから、文末記号が無くても確定させるまでの秒数。**下げる前に `stream_test.py` で delta の間隔を測ること。** 話し続けている間の間隔より短くすると、喋っている途中で切る |
| `IDLE_POLL_SEC` | 0.1 | 上のタイマーを見にいく間隔。細かいほど無駄な待ちが減る |
| `SPECULATE_AFTER_SEC` | 1.4 | 無音がこれだけ続いたら、確定を待たずに翻訳を投げる。当たれば字幕が約0.9秒早く出る。外れた分は捨てるので料金が増える。`0` で止める |
| `LINE_INTERVAL_SEC` | 0.6 | Zoom へ1行ずつ送る間隔。字幕の窓が最小4行しかないので、まとめて送ると先頭が押し出される。**閲覧画面には効かない**（全行すぐ出る） |
| `WEB_LINES` | 8 | 閲覧画面に出す行数 |
| `WEB_PORT` | 8080 | 閲覧画面 |
| `CONTROL_PORT` | 8081 | 操作画面 |

## 9. うまくいかないとき

| 症状 | 見るところ |
|---|---|
| 何も起きない。ログが流れない | **「字幕の生成」の開始を押したか。** 起動しただけでは動かない |
| `CABLE Output` が一覧に無い | VB-CABLE を入れたか。PC を再起動したか |
| 音量メーターが振れない | Zoom のスピーカー設定。両方 48000 Hz か。**「音声の入力」が `CABLE Output` か** |
| 「入力を開けない」と出る | 別のアプリが専有していないか。48000 Hz を受け付ける装置か。別の入力を選ぶ |
| 認識の行が出ない | `.env` の `OPENAI_API_KEY`。ネットワーク |
| 認識は出るが字幕が出ない | 翻訳のエラーが画面に出ているはず |
| ログは流れるが受信側に出ない | **ホストの画面を見ていないか**（ホストには出ない）。相手が「字幕を表示」をオンにしたか。トークンが今の会議のものか |
| 喋ると別の字幕が出る | **Zoom の自動字幕が動いている。** オフにする |
| 表にあるのに用語を外す | `ASR_KEYWORD_LIMIT` で切られていないか。表の末尾は認識に渡らない |
| 字幕が途中で止まった | `seq` が巻き戻った。アプリを再起動したなら `local/seq_state.json` を確認する |
| 字幕が速すぎて読めない | 受信側に表示領域を広げてもらう。`config.FORCE_CUT_CHARS` を下げる |
| 認識の再接続が増える | 回線。字幕PCの Zoom で受信ビデオを止める。別回線を試す |

**受信側を先に確かめること。** 送信が成功したことは、表示されている証明にならない。
2026-09-07 の試験では、送信は全て 200 なのに何も見えなかった。原因は受信側だった。

**字幕は時間では消えない。** 新しい行に押し出されるまで残っている。
見逃しても、送り直さずにもう一度見ればよい。
