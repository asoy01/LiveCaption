# LiveCaption マニュアル

The English version is [manual.md](manual.md).

LiveCaption は、会議にリアルタイムの字幕を出すシステムです。現時点では、日本語と英語の
間で翻訳できます。

字幕の向きは選べます。

- **日本語の会議に英語字幕**（日本語を話さない参加者のため）
- **英語の会議に日本語字幕**（英語で聞き取るのが負担な参加者のため）

Zoom に字幕を出せますが、Zoom 専用ではありません。音声は仮想オーディオ
ケーブルから取るので、音が出る会議ソフトなら何でも使えます。

**専用の Windows PC を1台使います。** その PC は会議に無言の参加者として入ります。
専用 PC を使う理由は「10. 仕組み」に書いてあります。

**予定を入れておけば、無人で動かせます。** 時刻が来たら Zoom に参加し、配信を始め、
会議が終わったら片付けます。「4. 予定した会議の自動処理」を見てください。

---

## 1. 必要なもの

| 品目 | 補足 |
|---|---|
| Windows PC 1台 | 字幕専用。|
| VB-CABLE | 無料の仮想オーディオケーブル。[vb-audio.com/Cable/](https://vb-audio.com/Cable/) |
| OpenAI の APIキー | 音声認識と翻訳の両方が OpenAI API を呼びます |
| pixi | Python 環境を作ります。[pixi.sh](https://pixi.sh) |
| Git | リポジトリを取ってくるのに使います |
| Zoom など会議ソフトのアカウント | 無料のもので構いません |
| ホストまたは共同ホストの権限 | Zoom字幕API を使う場合だけ。他の見せ方には要りません |

API料金は音声認識が **$0.017/分** です。1時間の会議で約1ドル、日本円で150円ほどです。
翻訳のAPI料金は無視できるほど小さいです。

会議が無音の時間も課金されるので、休憩の間は「停止」を押すとよいでしょう。
**ただし「停止」は配信とZoom字幕も一緒に止めます**（3の手順4を見てください）。
短い休憩なら、そのままにしておくほうが楽です。

## 2. インストール

インストールは字幕PCで一度だけ済ませます。

### 2.1 VB-CABLE のインストール

[vb-audio.com/Cable/](https://vb-audio.com/Cable/) からダウンロードします。
**インストーラは管理者権限で実行し、終わったら PC を再起動してください。**

### 2.2 CABLE の周波数設定（48000 Hz）

再起動後、Windows のサウンド設定で次の2つを確認します。

| デバイス | 形式 |
|---|---|
| `CABLE Input`（再生） | **48000 Hz**、16ビット |
| `CABLE Output`（録音） | **48000 Hz**、16ビット |

**両方を 48000 Hz に揃えてください。** 食い違うと Windows が再サンプリングし、音が
乱れます。LiveCaption は 48000 Hz で開いて、自分で 24000 Hz に落とします。

### 2.3 pixi のインストール

pixi は Python の環境を作るソフトです。**Python を別に入れる必要はありません。** pixi が
必要なバージョンの Python ごと用意します。

PowerShell を開いて、次のどちらかを実行します。

```powershell
winget install prefix-dev.pixi
```

```powershell
powershell -ExecutionPolicy ByPass -c "irm -useb https://pixi.sh/install.ps1 | iex"
```

**入れたあとは、PowerShell を開き直してください。** 開き直さないと、PATH の変更が
反映されません。pixi が入ったかどうかは、次のコマンドで確かめます。

```powershell
pixi --version
```

Git も同じように入れられます。既に入っていれば飛ばしてください。

```powershell
winget install Git.Git
```

### 2.4 リポジトリの取得

置き場所はどこでも構いません。日本語やスペースを含まないパスにしておくと安全です。

```powershell
cd C:\src
git clone https://github.com/asoy01/LiveCaption.git
cd LiveCaption
```

Git を使わない場合は、GitHub のページから ZIP をダウンロードして展開しても構いません。
ただし、ZIP を展開した場合は `git pull` で更新できなくなります。

### 2.5 Python 環境の構築

クローンしたフォルダの中で実行します。

```powershell
pixi install
```

必要なパッケージが `.pixi` フォルダの中に入ります。**pixi はシステムの Python を変更しません。**
初回は数分かかります。

### 2.6 APIキーの設定

**置き場所はリポジトリの直下です。** `pixi.toml` や `StartLiveCaption.bat` と同じ
フォルダに、`.env` という名前のファイルを作ります。

```
LiveCaption\
  ├ .env.example          見本。リポジトリに入っています
  ├ .env                  これを作ります
  ├ pixi.toml
  ├ StartLiveCaption.bat
  ├ src\
  └ ...
```

2.4 でクローンしたフォルダの中で、見本をコピーするのが早いです。

```powershell
copy .env.example .env
notepad .env
```

開いたら、キーを書き込んで保存します。

```
OPENAI_API_KEY=sk-...
```

キーは [platform.openai.com](https://platform.openai.com) で作ります。

**ファイル名は `.env` です。`.env.txt` ではありません。** メモ帳の「名前を付けて保存」で
新規に作ると `.txt` が付くことがあります。上の `copy` を使えば `.txt` は付きません。

`.env` は Git に入りません（`.gitignore` に書いてあります）。キーが誤って公開される心配は
要りません。

**`.env` の値が、同じ名前の環境変数より優先されます。** 両方に書いた場合、使われるのは
`.env` のほうです。

### 2.7 音声経路の確認

この確認に会議も APIキーも要りません。`CABLE Input` にサイン波を流しながら、
`CABLE Output` から読み返します。

```powershell
pixi run python scripts/cable_loopback.py
```

送った振幅が返ってくれば、VB-CABLE は正常です。

```
--- 本体が既定で選ぶもの: 2 'CABLE Output (VB-Audio Virtual ' [MME] ---
  区間 39、音あり 39（100%）  最大 peak 0.299  取りこぼし 0
  => 通っている
```

### 2.8 スタートメニューへの登録（任意）

**`InstallToStartMenu.bat`** をダブルクリックします。現在のユーザーのスタートメニューに
`LiveCaption` の項目が入るので、会議の前にこのフォルダを探さずに済みます。

**この項目はウィンドウを開きません。** タスクトレイに常駐し、アイコンを右クリックして
操作画面・ログ・終了を選びます（4.5 を見てください）。起動の様子を見たいときは、
`StartLiveCaption.bat` を手で実行してください。そちらはコンソールが残ります。

```
Windowsキー  ->  「livecaption」と打つ  ->  Enter
```

目に入る場所に置きたければ、スタートメニューの LiveCaption を右クリックして
**スタートにピン留めする** か **タスクバーにピン留めする** を選びます。

管理者権限は要りません。作られるのはショートカット1つで、置き場所は
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\LiveCaption.lnk` です。

**このフォルダを移動・改名したら、`InstallToStartMenu.bat` をもう一度実行してください。**
ショートカットは絶対パスを持っているので、フォルダを動かすと LiveCaption を開けなくなります。

アイコンは `etc/LiveCaption.ico` を使います。アイコンを変えるときは `scripts/make_icon.py` を
直して実行し、登録し直してください。登録を消すときは、端末から `-Remove` を付けて実行します。

```powershell
InstallToStartMenu.bat -Remove
```

### 2.9 遠隔操作の注意

字幕PCを別の部屋に置いて遠隔操作しても構いません。**ただし RDP（リモートデスクトップ）は
使えません。**

RDP は別のセッションを作ってコンソールセッションをロックし、音声を「リモートオーディオ」
へ振り替えます。**会議ソフトが選んでいた `CABLE Input` への経路が切れて、字幕が止まります。**

VNC 系のように、コンソールセッションをそのまま操作するソフトを使ってください。VNC 系なら
オーディオデバイスの構成は変わりません。

### 2.10 操作画面の遠隔利用（任意）

画面を丸ごと転送する遠隔操作は、遅延があって扱いにくいことがあります。操作画面は Web
ページなので、**別の端末のブラウザから直接開くほうが速くて確実です。**

Tailscale を使っている場合、次のように起動すると、操作画面が tailnet のアドレスでも
開けるようになります。

```
pixi run caption --web --control-bind
```

値を省くと、このPCの Tailscale アドレスを自分で調べます。起動時に次のように出ます。

```
操作画面:   http://localhost:8081  （自分だけ。共有しないこと）
            http://100.x.x.x:8081  （tailnet の中から。ACLで絞ること）
```

**127.0.0.1 は必ず残ります。** Tailscale が落ちていても、機体の前からは操作できます。
再起動の直後で Tailscale がまだ上がっていない場合は、取れるまで背景で試し直します。

**操作画面には認証がありません。** 守っているのは「どこから届くか」だけです。したがって:

- **tailnet の外には絶対に出さないでください。** Tailscale の範囲
  （`100.64.0.0/10`、`fd7a:115c:a1e0::/48`）以外のアドレスは受け付けない作りにしてあります
- **Tailscale の ACL で、届く端末を自分のものだけに絞ってください。** tailnet に他の人を
  招いている場合、この設定をしないと、その人たちも操作画面を開けます。開ければ、
  終了も、配信の開始も、**会議の文字起こしの閲覧**もできます

平文の HTTP になるので、**「URLをコピー」のボタンは効きません**（ブラウザの制限です）。
URLは選択された状態になるので、Ctrl+C でコピーしてください。機体の前で `localhost` から
開いたときは、従来どおり効きます。

## 3. 使用方法

### 手順1. アプリの起動

**`StartLiveCaption.bat`** をダブルクリックします。2.8 で登録してあれば、スタート
メニューの **LiveCaption** からでも構いません。操作画面がブラウザで開きます。

```
http://localhost:8081              操作画面   <- この画面は共有しないこと
http://localhost:8080/v/<ランダム>  閲覧画面   <- 共有するのはこちら
```

**操作画面を絶対に画面共有しないでください。** Zoom の字幕トークンが映っています。

**LiveCaption は、字幕の生成を止めた状態で始まります。** **開始**を押すまで、音は
取り込まれず、API も呼ばれません。会議に入る前に立ち上げておけます。準備中の雑談は
文字起こしに流れません。

#### 操作画面の見方

左が字幕、右が操作です。境目をドラッグすると幅が変わり、ダブルクリックで元に戻ります。

右は **会議** と **設定** の2枚に分かれています。

| タブ | 中身 | いつ見るか |
|---|---|---|
| **会議** | いまの状態・この会議・見せ方・会議の記録 | 会議のたび |
| **設定** | 音声の入力・用語集・遅延の調整・アプリの終了 | 据え付けるとき |

**当日触るものは、すべて「会議」の側にあります。** 設定の側は、一度合わせたらほとんど
開きません。

**「会議」に赤い丸が付いたら、そちらで何かが失敗しています。** 設定を開いたままでも
気づけるように出しています。

いちばん上の「見せ方」の3つは畳んであります。**畳んだままでも、見出しの右に
`配信中` や `送信中` と出るので、いくつ動いているかは分かります。**

### 手順2. 字幕PCの会議参加

字幕PCの会議ソフトで、次の3つを確かめます。

- **音声の出力先: `CABLE Input`。** 出力先が違うと、音が字幕アプリに届きません
- **マイク: ミュート。** この PC は発言しません
- **表示名: `Live Captions` など。** 参加者一覧に出るので、この PC が何をしているか
  分かるようにします

そのうえで会議に入ります。

操作画面は日本語と英語を切り替えられます。ヘッダの **日本語 / English** の欄で選ぶと、
その場で読み込み直します。**次の起動もその言語で始まります。**

**切り替わるのは操作画面だけです。** 字幕そのもの、文字起こし、会議の記録は訳しません。
閲覧画面は元から英語です。

### 手順3. 入力デバイスの確認

操作画面の**設定**タブを開き、「音声の入力」を見ます。`CABLE Output` になっている
はずです。違っていたら一覧から選んでください。**選んだ時点で切り替わります。適用ボタンはありません。**
あとから挿したデバイスが一覧に無ければ「一覧を更新」を押します。

一覧には名前だけでなくホストAPIも出ます。Windows では `CABLE Output` が
MME・DirectSound・WASAPI の3つに現れるためです。

```
2: CABLE Output (VB-Audio Virtual （MME、16 ch）
```

3つのどれでも動きます。既定は MME です。MME のままで構いません。

### 手順4. 字幕の向きの確認と生成の開始

操作画面の**会議**タブで、「この会議」の中の「字幕の向き」を見ます。**会議ごとに
選びます。**

| 選ぶもの | どんな会議か | 出る字幕 |
|---|---|---|
| 日本語 → 英語 | 日本語で行う会議 | 英語 |
| 英語 → 日本語 | 英語で行う会議 | 日本語 |

**選んだ時点で切り替わります。適用ボタンはありません。** 会議の途中で変えても構いません。
音声認識は繋ぎ直さないので、字幕の生成を止めずに切り替えられます。

**逆の言語が混ざったときは、訳さずにそのまま出します。** 日本語 → 英語 の会議で英語の
発言が来たら、その英語をそのまま字幕にします。**前半が英語で後半が日本語といった会議
でも、片方を選んでおけば足ります。**

**次の起動もこの向きで始まります。** 前回の選択を覚えています。

そのうえで、いちばん上の「いまの状態」の**開始**を押します。

**「停止」は3つとも止めます。** 字幕の生成だけでなく、参加者への配信（閲覧URL）と
Zoom字幕への送信も一緒に閉じます。**止めたつもりで流れ続けるのが一番困る**ためです。
配信を止めると閲覧URLは死ぬので、休憩のたびに押すものではありません。
何を止めたかは、押した後にその場に出ます。

**その下の音量メーターを見てください。** 誰も喋っていなければメーターは振れません。誰かに喋って
もらいます。人が喋っているのにメーターが振れないなら、入力デバイスが違います。別のデバイスを
選んでください。**生成中でも差し替えられます。**

### 手順5. 字幕の表示方法

字幕の見せ方は3つあります。**3つとも同時に使えます。**

| 方法 | ホスト権限 | 読み手がすること | 外に出るか |
|---|---|---|---|
| Zoom字幕API | **要る** | 各自が手動字幕をオンにする | Zoom経由 |
| 画面共有 | 要らない | 閲覧画面を全画面にして共有する | **出ない** |
| URL配布 | 要らない | 各自の端末でURLを開く | Cloudflare経由 |

#### A. Zoom字幕API（ホストまたは共同ホストの権限が必要）

トークンは会議中にしか作れません。作れるのはホストと共同ホストだけです。

1. ホストがツールバーの「字幕」の横の矢印を押し、**「手動字幕の設定」**を開いて、
   手動字幕を有効にします。**これを先にしないと「APIトークンをコピー」は出てきません**
2. 同じ場所から **「APIトークンをコピー」** を選びます
3. ホストがそのトークンを、会議のチャットで字幕PCに送ります
4. 操作画面の「見せ方」で **Zoomの字幕に流す** を開き、「APIトークン」にトークンを
   貼って**登録**を押します。入力欄は伏せ字で、登録すると空になります
5. **開始**を押します。まず捨て字幕が3つ流れます。**受信側は、字幕が流れ始めるまで
   手動字幕をオンにできません。** 最初の数行は誰にも届かないので、意味の無い
   3行を先に送っておきます

**Zoom の自動字幕をオフにしてください。** オンのままだと、LiveCaption の字幕が
押し出されて読めなくなります。

**操作画面の右上の表示を見てください。**

| 表示 | 意味 |
|---|---|
| `Zoom: 未登録` | トークンがまだ入っていない |
| `Zoom: 停止中` | 登録済み。「開始」を押せば送る |
| `Zoom: 送信中` | 送っている |
| `Zoom: 送信中（失敗 3）` | **送信が失敗している。** トークンが切れたか、会議が変わった |
| `生成: 停止中` | **字幕を作っていない。** Zoom を送信中にしても1行も流れない |
| `生成: 中` | 字幕を作っている |

**失敗の数を見逃さないでください。** Zoom は間違ったトークンに 200 以外を返すだけで、
理由を教えません。トークンを取り直して登録し直します。

#### B. 画面共有

ホスト権限が要らず、字幕が外に出ません。

1. 操作画面の「見せ方」で **画面共有で見せる** を開き、**閲覧画面を開く**を押します
2. **F11** で閲覧画面を全画面にします
3. 会議ソフトでそのブラウザの画面を共有します

**画面共有の映像は圧縮されます。** 小さい字は潰れます。共有を始めた後、2台目の端末から
字幕が読めるかどうか確かめてください。読めなければ行数を減らします（`config.WEB_LINES`）。

#### C. URL の配布

URL の配布もホスト権限が要りません。字幕PCから外向きにトンネルを張り、公開URLとQRコードを
作ります。

**経路は2つあり、「見せ方」の中の ブラウザで見てもらう を開いて、「経路」で選びます。**

| | Cloudflare | Tailscale |
|---|---|---|
| 準備 | 要りません | tailnet の設定が1回 |
| URL | **配信のたびに変わります** | **変わりません** |
| 前もって配れるか | 配れません | **配れます** |

その場で決まった会議には Cloudflare、前もって案内に載せたい会議には Tailscale を使います。

##### C-1. その場で配る（Cloudflare）

1. 「経路」を **Cloudflare** にします
2. **配信を開始**を押します。表示が `配信: 起動中…` から `配信: 中` に変わります
3. 字幕を見たい人にQRコードを見せるか、URLを送ります。
   **URLの下の「URLをコピー」を押せば、そのままチャットに貼れます**
4. QRコードを画像で配りたいときは、**「QRコードを保存」**を押します。PNG
   （656×656 ピクセル）がブラウザのダウンロードフォルダに落ちるので、
   案内のメールやスライドに貼れます
5. 各自が自分のスマホやノートで開きます

##### C-2. 前もって配る（Tailscale）

字幕PCのホスト名が変わらないので、**会議の前日でもURLが決まります。** Zoomのリンクと
一緒に案内に載せられます。

準備は1回だけです。字幕PCで次を実行し、ブラウザに出る同意のページを通します。
tailnet の管理者権限が要ります。

```
tailscale funnel 8080
```

有効になるのは、HTTPS証明書と、ポリシーの `funnel` 属性の2つです。

会議ごとの手順は次のとおりです。

1. 「経路」を **Tailscale** にします
2. 「会議」に会議の名前を入れて**追加**を押します。その会議のURLがその場で出ます
3. URLをコピーするか、QRコードを保存して、案内に載せます
4. **当日、その会議を選びます。** 左の丸印を押すと、配信する会議が切り替わります
5. **配信を開始**を押します

**配信するのは選んである1つだけです。** 他の会議のURLは、その日には開けません。
先週の会議の参加者が、今日の字幕を見ることはありません。

**URLが固定である点は、弱点でもあります。** 守っているのはURLの後半の文字列だけなので、
漏れたら会議を消して作り直してください。

**どちらの経路でも、既定では配信しません。** 字幕は Cloudflare か Tailscale を通ります。
**外部に出せない内容を扱う会議では、URL の配布を使わないでください。**
代わりに画面共有を使います。

### 手順6. 参加者への案内

会議の冒頭で、字幕を読む人に次を伝えます。

- **各自が手動字幕をオンにすること。** オンにした人にしか字幕は見えません
- **字幕の表示領域をドラッグして広げること。** 既定は4行です。4行では翻訳を読む余裕が
  ありません

### 手順7. 終了

操作画面の**設定**タブを開き、「アプリの終了」の**終了**を押します。ブラウザのタブも
ターミナルのウィンドウも閉じます。タスクトレイから起動した場合は、アイコンを右クリック
して**終了**でも同じです。

## 4. 予定した会議の自動処理

ここまでは、会議のたびに人が操作画面の前に座る使い方です。**予定を入れておけば、
時刻が来たときに自動で動かせます。** 字幕PCを常時起動しておく運用を想定しています。

自動で行うのは次の4つです。

1. 会議を選び、配信を開始する
2. Zoomに参加する
3. 字幕の生成を開始する
4. 会議が終わったら、離脱して停止する

**字幕APIトークンだけは自動で取れません。** 会議中にホストしか作れないためです。
受け取り方は「4.4 ホスト用URL」にあります。

### 4.1 予定の入力

操作画面の「この会議」にある**会議の管理**を押すと、別のタブで管理画面が開きます。
会議の行の**予定**を押すと、入力欄が開きます。

| 欄 | 意味 |
|---|---|
| 開始 | 会議の開始時刻 |
| 毎週 | 同じ曜日・同じ時刻で繰り返す |
| Zoom | 招待URL（`https://zoom.us/j/...`）か会議番号。空なら自分では参加しません |
| 何分前から | この分だけ前に、配信とZoom参加を始めます |
| 無音で終了（分） | 文字起こしがこの分だけ出なければ、会議が終わったとみなします |
| 安全上限（分） | 無音でなくても、この時間で必ず止めます |
| この会議を自動で回す | **この印が付いた会議だけが自動で動きます** |

**「自動で回す」の既定は切りです。** 自動で回すと、人が見ていなくても字幕が外に出ます。
外に出せない内容を扱う会議には、印を付けないでください。

繰り返しは「毎週」だけです。より複雑な予定には対応していません。

### 4.2 動作の確認

操作画面の**会議**タブのいちばん上、「いまの状態」に出ます。

```
いまの状態
[開始] [停止]  止まっている
待機中
2026-09-25 10:00  KAGRA朝礼         あと 23 分
2026-09-27 13:00  共同研究者会議     あと 2 日 3 時間
[いま止める] [次の予定を飛ばす]
```

動いている間は、無音で終了するまでの残り時間と、安全上限までの残り時間が出ます。

**失敗は、押して消すまで残ります。** 無人で動かす以上、流れてしまった失敗は誰も見ません。
内容を確かめたら「了解」で消してください。

**「次の予定を飛ばす」** は、その回だけ休むときに使います。予定そのものは残ります。

### 4.3 Zoom側の設定

自動参加を使う場合、Zoomクライアント側で**1回だけ**次を設定してください。毎回は要りません。

- 音声の出力先 `CABLE Input`、マイクはミュート（手順2と同じ）
- 参加時にマイクをミュート
- 参加時にビデオをオフ
- **「コンピューターオーディオに参加」の確認を出さない**

最後の1つが特に重要です。**この確認が出たままだと、参加はできても音が繋がりません。**
無人では誰も押せないので、原因の分かりにくい失敗になります。

入れたのに音が来ない状態が5分続くと、操作画面に次のように出ます。

> Zoomから音が来ない。パスコード違いか、待機室で止まっているか、更新のダイアログが
> 出ている可能性がある。画面を見ること。

**個人リンク（`https://zoom.us/my/...`）には対応していません。** 会議番号が入っていないためです。
番号入りの招待URL（`/j/...`）を使ってください。

**Zoomから出る手段は、クライアントを終了させることだけです。** 会議から出る操作を外から
頼む口がないためです。**自分で参加した会議は終了させません。** 手で入っていた会議を
巻き添えにしないよう、こちらが参加させたときだけ終了させます。

### 4.4 ホスト用URL

字幕PCがホストでない会議でも、ホストに協力してもらえば Zoom字幕を出せます。

会議ごとに、参加者用とは**別の秘密のURL**を作れます。予定の入力欄の
**ホスト用URLを出す**を押すと表示されます。

**このURLはホストにだけ渡してください。** 参加者用のURLと取り違えないこと。
このURLを持つ人は、その会議の字幕をZoomへ流し込めます。

ホストがそのURLをブラウザで開くと、トークンを貼る画面が出ます。貼って送ると、
字幕PCがZoomへ字幕を送り始めます。

**このURLは、経路が Tailscale のときだけ作られます。** Cloudflare では作りません。
TLS が Cloudflare 側で終わるため、Zoomの資格情報がそこを平文で通るためです。

受け付けるのは次の場合だけです。

- いま配信している会議であること
- 予定の前後30分か、その会議を動かしている間であること
- 1回だけ（2回目からは断ります。操作画面の「もう一度受け付ける」で開き直せます）

**URLが漏れたら、その会議を消して作り直してください。**

### 4.5 常駐と自動起動

`StartLiveCaptionTray.vbs` をダブルクリックすると、**ウィンドウを出さずに**タスクトレイへ
常駐します。

| アイコンの色 | 状態 |
|---|---|
| 青 | 待機中 |
| 緑 | 字幕を出している |
| 赤 | 失敗が残っている |

マウスを乗せると、次の会議か、いま出している会議が出ます。右クリックで操作画面・ログ・終了。

ウィンドウが無いので、ログは `local/log/` に残ります（20本まで）。

**`StartLiveCaptionTray.vbs` を編集するときは、ASCII だけで書いてください。**
Windows はこのファイルを UTF-8 として読みません。日本語のコメントを入れると、
**ダブルクリックしても何も起きません。エラーも出ません。** ファイルの冒頭にも
英語で注意書きがあります。

Windows のログオン時に自動で起動させるには、次を実行します。管理者権限は要りません。

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install_autostart.ps1
```

外すときは `-Remove` を付けます。

**字幕PCはログオンしたままにしてください。** 画面のロックは構いません。ログオフすると
動けません。再起動のあとは、誰かがログオンするまで字幕アプリは上がりません。

## 5. 用語対訳表

専門用語をどれだけ正しく出せるかは、`etc/glossary/` の表で決まります。**主に保守するのは、この表です。**

### 自分の分野の表の作成

**分野ごとに1ファイル置きます。** 置き場は `etc/glossary/` で、拡張子は `.tsv` です。

見本が [glossary-example.tsv](glossary-example.tsv) にあります。これを
`etc/glossary/` にコピーして、自分の会議に出る語に置き換えてください。

```powershell
copy docs\glossary-example.tsv etc\glossary\MyProject.tsv
```

**`etc/glossary/` は Git に入りません。** 表には人名や組織名を入れると効きますが、
それを共有したくないためです。表は各自の手元に残ります。

分けておく理由は2つあります。1つは、会議に要らない語を外せることです。もう1つは、文字起こしに
渡せる語数に上限があることです（`config.ASR_KEYWORD_LIMIT`、既定 200）。1つの大きな表を全部の
会議で使うと、関係の無い語が上限を占めて、本当に要る語が渡らなくなります。

### 書式

1行に1語、3列をタブで区切ります。

```
日本語（正しい表記）  <TAB>  English  <TAB>  よくある誤認識（カンマ区切り）
```

この表は2か所で使います。

1. **文字起こし。** 日本語と英語の表記を、キーワードとして文字起こしのモデルに渡します。用語を正しく
   聞き取る確率が上がります
2. **翻訳。** 表全体を翻訳のプロンプトに入れ、第3列から置換規則を組み立てます

**効くのは第3列です。** 文字起こしはそれでも間違えます。実際に出た誤りを書いておくと、翻訳側が
そこから正しい用語を復元できます。

### 会議ごとの表の選択

操作画面の**設定**タブにある「用語集」の行は畳んであります。**いまどの表を使っているかは、畳んだままでも
見えます**（表の名前と合計の語数）。行を押すと一覧が開くので、使う表にチェックを
入れてください。**チェックした時点で切り替わります。**

表が8個以上になると、一覧の上に絞り込みの欄が出ます。**チェックを入れた表は、絞り込みで
他が消えても残ります。** 見えていない表のチェックを外せてしまうと、どの表を外したのか
分からなくなるためです。「全部選ぶ」「全部外す」は、絞り込みで隠れている表にも効きます。

チェックの下の行に、合計の語数と、文字起こしに渡す語の数が出ます。**上限に気をつけてください。**
`config.ASR_KEYWORD_LIMIT` を超えた語は文字起こしに届きません。上限を超えたときは語数が赤で表示されるので、表を
減らします。

**LiveCaption は表の選択を覚えています。** 次の起動も同じ組み合わせで始まります。起動時に決めることも
できます。

```powershell
pixi run caption --web --glossary 表の名前1 表の名前2
```

**同じ日本語が複数の表にあるときは、1つにまとめます。** 英語は最初に見つけた表のものを
使い、第3列の誤認識は全部の表から集めます。英語が食い違ったときは、食い違いを画面に出したうえで、最初の表の
ほうを使います。

### 会議後の表の更新

1. ダウンロードフォルダの `live-caption_*.md` を開きます。冒頭に、その会議で使った表の
   名前が書いてあります
2. 訳が誤っている用語を探します
3. 元の誤った文字起こしを、その用語が載っている表の第3列に足します

第3列に入れるものは3種類あります。

- **同音の誤変換。** 例:「光軸」が「校則」になる
- **英語の誤認識。** 略語が普通の英単語に化ける。例: `PID` が「peed」になる
- **前の語の末尾が食い込んだ形。** 文字起こしは音の切れ目を誤ります。「この回折」が「子の解析」に
  なったなら、`回折` の行の第3列に「子の解析」を入れます。**前の語ごと入れるのが正しい。**
  そう書き起こされるからです

**推測で入れないでください。** 意味の通らない語が残ったら、話していた人に聞きます。
音声だけから正解を当てられないことがあります。

**足したつもりの語が入っているとは限りません。** 判定に使う語は、実際に翻訳側へ通して
確かめてください。

## 6. 会議の記録

**LiveCaption は既定で会議の記録を残します。** 何も指定しなくて構いません。

置き場は、はじめは**ユーザーのダウンロードフォルダ**です。

```
ダウンロード/live-caption_2026-09-08_143012.jsonl   1文ごとに追記する
ダウンロード/live-caption_2026-09-08_143012.md      読める形。終了時に書く
```

### 置き場の変更

操作画面の**会議**タブ、「会議の記録」の中にあります。選び方は3つです。

**フォルダを選ぶ**を押すと、画面の中にフォルダの一覧が開きます。名前を押すと中へ入り、
**↑ 上へ**で戻ります。入りたいフォルダまで辿ったら**ここにする**を押します。
**別の機体から開いた操作画面でも、同じように使えます。**

出るのは**ホームフォルダ（`C:\Users\<名前>`）の下だけ**です。操作画面には認証が無いので、
ディスク全体を見せる口をここに作っていません。

パスを直接入れて、**この場所にする**を押しても構いません。**ホームフォルダの外でも
指定できます。無いフォルダは作ります。** 書けないフォルダは断ります。

字幕PCの前に座っているときだけ、一覧の下に **Windowsの窓を開く** が出ます。
**この窓は字幕PCの画面に出る**ので、別の機体から開いた操作画面では使えません
（押した人には何も見えないまま、字幕PCの画面に窓が残ってしまうため、断る作りに
してあります）。

どれで選んでも、切り替わるのはその場です。`.env` にも書くので、**次の起動もその置き場で
始まります。** いま開いている記録は、その場で閉じて新しい置き場に開き直します。

起動のたびに変えたいときは `--save-dir` を使います。こちらは `.env` より優先します。

文字起こしと字幕が対になっています。時刻は**文字起こしが確定した時刻**です。

`.jsonl` には遅延の実測も入ります。`.md` には出ませんが、後から遅延の設定を調整するのに要ります。

| 項目 | 意味 |
|---|---|
| `cut` | 文が確定した理由。`punct`（文末記号）/ `force`（長さ）/ `idle`（無音）/ `flush`（終了時） |
| `waited` | 無音で確定したときに、実際に待った秒数 |
| `took` | 翻訳にかかった秒数 |
| `total` | **確定から最初の字幕までの秒数。** `total − took` が待ち行列 |
| `spec` | 先回りの翻訳が当たった文に付く。このとき `total` は `took` より小さくなる |
| `dir` | そのときの字幕の向き |

- 会議中に読みたければ、操作画面の「会議の記録」の**途中まで読む**を押します
- **`.md` が書かれるのは終了時です。** 電源ごと落ちたときは
  `pixi run python scripts/transcript_to_md.py` で `.jsonl` から作り直します
- 記録を残したくないときは `--no-save` を付けて起動します
- 1文も出なかったときは、ファイルを残しません

## 7. コマンド一覧

会議で使うのはバッチファイルです。以下に、バッチファイル以外の起動方法も並べます。

```powershell
StartLiveCaption.bat                             # 会議で使うのはこれ
StartLiveCaptionTray.vbs                         # 窓を出さずにタスクトレイへ常駐する
InstallToStartMenu.bat                           # スタートメニューに登録する（最初に1回）

pixi run web                                     # 同じもの。端末から起動する場合
pixi run caption --web                           # 同上
pixi run caption --token "<URL>" --web           # Zoom字幕とブラウザ字幕の両方
pixi run caption --token "<URL>"                 # Zoom字幕だけ
pixi run caption --web --no-save                 # 記録を残さない
pixi run caption --check-audio 20                # 音量だけ見る（API不要）
pixi run devices                                 # 入力デバイスの一覧
pixi run caption --from-file recording.wav --dry-run   # WAVを実時間で流す
pixi run python scripts/transcript_to_md.py      # 落ちたあとに .md を作り直す
pixi run python scripts/cable_loopback.py        # VB-CABLE の経路を試す
```

オプション:

| オプション | 意味 |
|---|---|
| `--token <URL>` | Zoom字幕APIのトークン。あとから操作画面に貼っても構いません |
| `--direction <向き>` | 字幕の向き。`ja2en`（日本語の会議に英語字幕）か `en2ja`（英語の会議に日本語字幕）。既定は前回の選択 |
| `--glossary <名前> ...` | 使う用語集（`etc/glossary/` の .tsv の名前）。複数を重ねられます。既定は前回選んだ組み合わせ |
| `--device <名前>` | 入力デバイス名の一部。既定: `CABLE Output` |
| `--web [ポート]` | ブラウザに字幕を出します。閲覧側のポート、既定 8080 |
| `--control-port <ポート>` | 操作画面のポート、既定 8081 |
| `--control-bind [アドレス]` | **操作画面を tailnet からも開けるようにします。** 値を省くと自分で調べます。127.0.0.1 は必ず残ります。**Tailscale の範囲以外は受け付けません**（2.10 参照） |
| `--tray` | **タスクトレイに常駐します。** ログは `local/log/` にも残ります |
| `--web-bind <アドレス>` | **閲覧画面**が待ち受けるアドレス、既定 127.0.0.1。同じLANの端末から直接見せるなら 0.0.0.0。操作画面はこの設定の影響を受けません |
| `--tunnel` | 起動時からトンネルを張ります。既定では張りません |
| `--no-browser` | ブラウザを自動で開きません |
| `--no-save` | 会議の記録を残しません |
| `--save-dir <フォルダ>` | 記録の置き場。**操作画面で選んだ置き場より優先します。** 既定はダウンロードフォルダ |
| `--dry-run` | Zoom には送らず、画面に出すだけ |
| `--from-file <wav>` | デバイスの代わりに WAV を実時間で流します。24 kHz モノラル |
| `--loop` | `--from-file` のファイルを繰り返します |
| `--delay <段階>` | 文字起こしの遅延と精度。`minimal`・`low`・`medium`・`high`・`xhigh`。既定 `low` |
| `--model <名前>` | 翻訳のモデル。既定 `gpt-4.1-mini` |
| `--check-audio [秒]` | 音量を表示して終わります。API を呼びません |
| `--list-devices` | 入力デバイスの一覧を出します |
| `--cloudflared <パス>` | `cloudflared` の場所。PATH か `local/bin` にあれば要りません |

自動起動の登録と解除:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install_autostart.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install_autostart.ps1 -Remove
```

**ポートが埋まっているときは、両方の番号を変えてください。** 8081 は操作画面のものなので、
閲覧側に 8081 を指定してはいけません。

```powershell
pixi run caption --web 8090 --control-port 8091
```

## 8. 設定

`src/live_caption/config.py` にあります。既定値は実測で決めたものなので、理由があるときだけ
変えてください。

**下の4つは、操作画面と `.env` の両方から変えられます。** コードを直す必要はありません。

### 操作画面からの変更

**設定**タブの「遅延の調整」の行を押すと、入力欄が開きます。**よく変えるものではないので
畳んであります。**

- 数字を直して欄から離れると、**その場で効きます。再起動は要りません**
- **`.env` に保存** を押すと、次の起動でも同じ値で始まります。`.env` の他の行
  （`OPENAI_API_KEY` など）は消えません
- **既定に戻す** で実測で決めた値へ戻ります
- 既定と違う値があるときは、畳んだままでも見出しに「N 個を既定から変えている」と出ます

### `.env` への直接記述

書き方は `.env.example` にあります。

| `.env` の名前 | 対応する設定 |
|---|---|
| `LIVECAPTION_IDLE_FLUSH_SEC` | `IDLE_FLUSH_SEC` |
| `LIVECAPTION_SPECULATE_AFTER_SEC` | `SPECULATE_AFTER_SEC` |
| `LIVECAPTION_FORCE_CUT_CHARS` | `FORCE_CUT_CHARS` |
| `LIVECAPTION_LINE_INTERVAL_SEC` | `LINE_INTERVAL_SEC` |

差し替えると、起動時に `[設定] .env で差し替えた: …` と出ます。

**`IDLE_FLUSH_SEC` だけを変えると、`SPECULATE_AFTER_SEC` も自動で追随します**
（`IDLE_FLUSH_SEC − 1.1` 秒）。合わせないと、先回りの翻訳が早すぎて、捨てる翻訳が増えるだけに
なります。

**書き間違えても会議は止まりません。** 数字として読めない値や小さすぎる値を書いたときは、警告を出して
既定値のまま動きます。ただし**黙って無視はしません**ので、起動時の表示を見てください。

### 主な設定

| 設定 | 既定 | 意味 |
|---|---|---|
| `ASR_MODEL` | `gpt-live-transcribe` | 音声認識のモデル |
| `ASR_DELAY` | `low` | 実会議の録音で4段階を比べたところ、`minimal` と `high` はどちらも専門用語を取り違えました |
| `ASR_LANGUAGES` | `("ja", "en")` | **言語を1つに固定してはいけません。** 会議の途中で言語が切り替わることがあります |
| `ASR_KEYWORD_LIMIT` | 200 | 文字起こしに渡す用語の数の上限。**表の語数より大きくしておいてください。** 切り捨てが起きたら起動時に警告が出ます |
| `TRANSLATE_MODEL` | `gpt-4.1-mini` | 翻訳のモデル |
| `CONTEXT_SENTENCES` | 3 | 翻訳に文脈として渡す直前の文の数 |
| `MAX_CAPTION_CHARS` | 80 / 40 | 字幕1行の最大文字数。向きで変わります（英語80、日本語40） |
| `FORCE_CUT_CHARS` | 70 / 140 | これより長い文は強制的に切ります。向きで変わります（日本語を聞くとき70、英語140）。字幕が速すぎるなら下げてください |
| `IDLE_FLUSH_SEC` | 2.5 | 発話が途切れてから、文末記号が無くても確定させるまでの秒数。**下げる前に `stream_test.py` で delta の間隔を測ってください。** 話し続けている間の間隔より短くすると、喋っている途中で文を切ります |
| `IDLE_POLL_SEC` | 0.1 | 上のタイマーを見にいく間隔。細かいほど無駄な待ちが減ります |
| `SPECULATE_AFTER_SEC` | 1.4 | 無音がこれだけ続いたら、確定を待たずに翻訳を投げます。当たれば字幕が約0.9秒早く出ます。外れた分は捨てるので料金が増えます。`0` にすると先回りを止めます |
| `LINE_INTERVAL_SEC` | 0.6 | Zoom へ1行ずつ送る間隔。字幕の表示領域が最小4行しかないので、まとめて送ると先頭が押し出されます。**閲覧画面には効きません**（全行すぐ出ます） |
| `WEB_LINES` | 8 | 閲覧画面に出す行数 |
| `WEB_PORT` | 8080 | 閲覧画面 |
| `CONTROL_PORT` | 8081 | 操作画面 |

## 9. トラブルシューティング

| 症状 | 見るところ |
|---|---|
| 何も起きない。ログが流れない | **「いまの状態」の開始を押しましたか。** 起動しただけでは動きません |
| `CABLE Output` が一覧に無い | VB-CABLE を入れましたか。PC を再起動しましたか |
| 音量メーターが振れない | 会議ソフトのスピーカー設定。両方 48000 Hz か。**設定タブの「音声の入力」が `CABLE Output` か** |
| 「入力を開けない」と出る | 別のアプリが専有していないか。48000 Hz を受け付けるデバイスか。別の入力を選んでください |
| 文字起こしの行が出ない | `.env` の `OPENAI_API_KEY`。**`.env` はリポジトリ直下（`pixi.toml` と同じ場所）にありますか。名前が `.env.txt` になっていませんか。** ネットワークも確認 |
| 文字起こしは出るが字幕が出ない | 翻訳のエラーが画面に出ているはずです |
| ログは流れるが受信側に出ない | **ホストの画面を見ていませんか**（ホストには出ません）。相手が手動字幕をオンにしたか。トークンが今の会議のものか |
| 喋ると別の字幕が出る | **会議ソフトの自動字幕が動いています。** オフにしてください |
| 表にあるのに用語を外す | `ASR_KEYWORD_LIMIT` で切られていないか。表の末尾は文字起こしに渡りません |
| ある分野の用語がまとめて外れる | その分野の表にチェックが入っていません |
| 字幕が途中で止まった | `seq` が巻き戻りました。アプリを再起動したなら `local/seq_state.json` を確認してください |
| 字幕が速すぎて読めない | 受信側に表示領域を広げてもらいます。`config.FORCE_CUT_CHARS` を下げてください |
| 文字起こしの再接続が増える | 回線です。字幕PCの会議ソフトで受信ビデオを止め、別回線を試してください |
| 遠隔操作したら字幕が止まった | **RDP で入っていませんか。** 音声経路が切れます（2.9 を見てください） |
| 予定の時刻になっても始まらない | **「この会議を自動で回す」に印が付いていますか。** 既定は切りです。「いまの状態」に予定が並んでいるかも確認してください |
| Zoomに入ったのに音が来ない | **「コンピューターオーディオに参加」の確認が出たままになっていませんか**（4.3）。待機室で止まっている、パスコードが違う、という可能性もあります |
| 会議が終わっても離脱しない | 無音で終了するまでの分を確認してください。安全上限に達すれば必ず止まります |
| 会議が早く終わったのに動き続ける | 誰かのマイクが開いたままだと、音が続くので無音になりません。「いま止める」を押してください |
| 自動起動しない | ログオンしていますか。**ログオフしていると動けません。** タスクスケジューラで `LiveCaption` の状態を見てください |
| トレイのアイコンが出ない | ログ（`local/log/`）を見てください。窓が無いので、そこが唯一の手がかりです |
| tailnet から操作画面が開けない | `--control-bind` を付けて起動しましたか。Tailscale が上がっていますか。ACL で塞いでいませんか |

**受信側を先に確かめてください。** 送信が成功しても、受信側に字幕が表示されているとは限りません。
送信が全て HTTP 200（成功）なのに受信側に何も出ていない、ということが実際に起きます。原因は受信側に
あります。

**字幕は時間では消えません。** 新しい行に押し出されるまで残っています。見逃しても、
送り直さずにもう一度見れば済みます。

## 10. 仕組み

ここから先の説明は、LiveCaption を使うだけなら読まなくて構いません。

### 専用 PC が必要な理由

```
[ホストPC]        通常どおり会議を進める
     |
[字幕PC]
  会議ソフト ----- 無言の参加者として参加、マイクはミュート
   |
   +-- スピーカー出力 --> CABLE Input
                             |   (VB-CABLE、仮想オーディオケーブル)
                          CABLE Output --> LiveCaption
                                             |-- 音声認識
                                             |-- 翻訳
                                             +-- 出力
```

**LiveCaption をホスト PC で動かしてはいけません。** 会議ソフトは自分のマイク音声を自分のスピーカーに
流しません。ホスト PC でスピーカー出力を録ると、**ホスト自身の声が入りません。**
字幕PCは会議ソフトからミックス音声を受け取るので、その中に全参加者の声が入っています。

仮想オーディオケーブルを使うので、字幕アプリは `CABLE Output` を普通の録音デバイスとして
開くだけで済みます。WASAPI のループバックAPIを使わないため、音量やミュートの影響を
受けません。

### 用語対応の2段構成

LiveCaption は、専門用語を正しく出すために、音声認識だけに頼りません。

1. **文字起こし側。** 用語表の語をキーワードとして渡し、固有名詞の音を拾わせます
2. **翻訳側。** 用語対訳表と、実際に出た誤認識からの置換規則と、直前3文の文脈を
   モデルに渡します。**ここが本命です**

文字起こし側が音の近い誤りをしても、文脈と用語表があれば翻訳側で復元できます。
**ただし全部は直せません。** 誤認識が別の妥当な専門用語になると、流暢な誤訳が
出ます。

### 確定した文だけを送る理由

途中経過を出して後から書き換えると、読み手は追えません。字幕は蓄積されて置き換わらないので、
途中経過を送ると、その途中経過が1行として残り、訂正した完成版がその下に並びます。
**読み手には同じ内容が2回見えます。**

このため、LiveCaption は翻訳にかかる時間をストリーミングで隠せません。

### 遅延

遅延は文の終わり方で変わります（実測）。

| | 文字起こし | 確定待ち | 翻訳 | 送信 | 合計 |
|---|---|---|---|---|---|
| 文末記号で終わった文（約74%） | 0.2〜1秒 | 0秒 | 0.9秒 | 0.3秒 | **約1.5〜2秒** |
| 無音で終わった文（約9%） | 同上 | 2.5秒 | 0.9秒 | 0.3秒 | **約4秒** |

残りの約17%は、文末記号が来ないまま長くなって強制的に切った文です。確定を待たないので、
遅延は文末記号で終わった文と同じです。

無音で終わった文は、確定を待つ間に先回りで訳しておきます（`SPECULATE_AFTER_SEC`）。
当たれば翻訳の 0.9秒 が消えます。

**確定待ちは下げられません。** 文字起こしの出力が途切れる間隔を測ると、話し続けている最中でも
2.5秒 近く空くことがあります。閾値を下げると、喋っている途中で文を切る回数が増えます。
